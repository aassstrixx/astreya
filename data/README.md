# Данные сайта

Единственный источник содержимого. После правки запустите `node tools/build.js`.

## Что проверено, а что — placeholder

* **Проверено по открытым источникам (acosm.ru / academy.acosm.ru):** состав брендов и их направления, контакты офисов и представительств, режим семинаров (10:30–18:00),
  бесплатность базовых семинаров, преподаватель С. В. Савиных.
* **Демонстрационное (заменить):** карточки товаров (30 позиций — без объёма, артикулов, документов), даты и темы мероприятий (`demo: true`), тренеры без ФИО,
  новости и акции (`demo: true`), пороги скидок (5/10/15 % — пример), число «20 лет» (из описания учебного центра — уточнить формулировку), реквизиты (`null` → «Уточняется»).
* **Страна бренда:** Dermatime и Keenwell — «Испания» (по описанию бренда); линии Cantabria Labs — «страна концерна: Испания»; EVA — не указана (`null`).
* **Логотипы брендов:** файл лежит в `assets/brands/` (`<id>.svg` или `.png`), путь указан в поле `logo` бренда. Лучше SVG (на странице бренда он остаётся чётким при любом размере); у PNG нужен **прозрачный фон** и обрезанные поля. На цветных плашках карточек логотип автоматически показывается одним цветом (белым, а при тёмном `ink` бренда — чёрным), на странице бренда — в исходных цветах. Если `logo` пустое (`null`), вместо картинки остаётся текстовое название/монограмма. Размер подбирается автоматически так, чтобы логотипы разной формы выглядели одинаково крупными (одна «площадь»); у очень плотных знаков можно уменьшить/увеличить его полем `logoScale` (по умолчанию 1, у EVA 0,88). Логотипы Cantabria Labs (Biretix, Endocare, Neoretin, Heliocare, Iraltone) — отдельные векторы SVG в едином макете: знак «cantabria labs» над названием; сам знак лежит отдельными файлами `assets/brands/cantabria-labs.svg` (столбиком, как на исходном фото) и `assets/brands/cantabria-labs-h.svg` (в строку, для небольших плашек и шапок).
* **Фото товаров:** пока CSS-иллюстрация упаковки (`type`: bottle, dropper, jar, pump, tube, box, device).

## Поля

**products.json** — `id, slug, brand, cat, kind, type, name, desc, tasks[], isNew, featured` и необязательные (пока `null`/пусто → «Уточняется»):
`volume, sku, usage, indications[], actives[], docs[{title,url}], details[]` (полное описание абзацами; если пусто — собирается из `desc` и данных бренда).

**events.json** — `id, slug, date (YYYY-MM-DD), city, fmt ("Очно"|"Вебинар"), time, brand, title, teacher (id из training.json), speaker, place, description, seats (число или null), demo`.
Прошедшие мероприятия автоматически скрываются в списках и на странице мероприятия.

**news.json** — `categories[]` (news, sale, novelty, edu, event) и `items[]` с `slug, category, date, title, excerpt, body[], cta{type,ref,query}, related{brands,products,events}`.
В тексте можно использовать `{{discounts}}` — подставятся пороги из `site.json`.

**site.json** — `url` (адрес сайта для canonical и sitemap), `formEndpoint` (адрес приёма заявок: `/api/lead` — сервер из `server/` на том же адресе, заявки идут в админку; для сайта на Pages — полный `https://<сервер>/api/lead`; пусто — формы готовят письмо; см. server/README.md), `demoNotice` (пустая строка убирает заметку в подвале и включает Product/Event/NewsArticle JSON-LD).

**integrations.json** — подключения для российского рынка (правится в админке: «Интеграции»): `metrika` (номер счётчика, Вебвизор, цели `goals[{id,name,key}]`), `consent` (режим `optin` / `notice` / `off`, тексты уведомления о cookie), `verification` (коды подтверждения Яндекс Вебмастера, Google, Mail.ru), `messengers` (ссылки `max`, `telegram`, `vk` и флаг `showEmpty` — показывать канал без ссылки ячейкой «Скоро»), `captcha.siteKey`. Токены и серверные ключи сюда не попадают — они хранятся на сервере. Пустой номер счётчика — Метрики и уведомления о cookie нет.

**legal.json** — данные для политики конфиденциальности, согласия и пользовательского соглашения (`src/legal.js`): дата редакции, e-mail для обращений, ответственный, `storageInRussia`, текст срока хранения, получатели данных `processors[{name,purpose,country}]`, предупреждение про ИИ-помощника. Реквизиты оператора берутся из `site.json → requisites`; пока они не заполнены, на страницах `privacy.html`, `consent.html`, `terms.html` — заглушки.

**content.json → forms** — тексты форм (заголовок, тема заявки, подводка, кнопка, подсказка, подпись у согласия, сообщение после отправки). Поля форм и обязательность менять нельзя (их задаёт `js/shared.js`). **site.json →** `ogImage`, `schemaAddress` — картинка для соцсетей, адрес в разметке организации (текст подвала — `redesign.json → footer.tagline`).

**stella/** — библиотека «живых» реплик помощника Стеллы (ответы на неожиданные вопросы без ИИ): `config.json` и темы по файлам; формат и правила записи — в `data/stella/README.md`. Нет папки — библиотека выключена. Правится в админке («Содержимое сайта» → группа «Помощник Стелла», по разделу на файл) или в репозитории; после правок в репозитории — `node tools/build.js` и `node tools/check-stella.js` (админка проверяет только, что сайт собирается).

## Слой доработок: `redesign.json` и флаг `site.redesign`

* `site.json → redesign` (`true`/`false`) включает/выключает весь слой (см. README → «Доработки и откат»).
* `redesign.json`: подписи и состав новых секций главной (цифры, «Почему Астрея», решения, блок брендов, editorial, обучение, «Для кого», финальный призыв), колонки подвала, страница «Бренды» (`brandsPage.deviceIds` — бренды-устройства, показываются отдельной группой), шаг «Для кого?» подборщика.
* Цифры «Астрея в цифрах» берутся из `content.json → home.stats`; дополнительные показатели — `redesign.json → stats.extra`: пока `value = null`, блок не показывается. **Ничего не выдумывается** — впишите реальное значение, и оно появится.
* Заглушки (`"placeholder": true`, `photo: null`) нужно заменить реальными данными и фото. Для фото специалиста/обучения: положите файл в `assets/photos/` и укажите путь в `editorial.photo` / `training.photo`.
* **Фото 01–05** (`redesign.json → photos`, файлы в `assets/photos/`): 01 `hero` — мягкий фон слева за текстом главного экрана (шар с орбитами остаётся справа); 02 `about` (+ `about2`, `about3`) — «О компании» (слева: главное фото и два дополнительных; на трёх фото — по слову лозунга «Наука. Забота. Результат.»); 05 `expertise` — блок «Экспертиза» (слева). Чтобы заменить фото — положите новый файл и поправьте `src`, `w`, `h`, `alt`. Каждое фото используется только в своём блоке.
* **Пометки «демо / placeholder»**: `redesign.json → ui.showDemoNotices = false` скрывает их в интерфейсе (подвал, каталог, бейдж у показателей). Данные остаются в `site.json`/`content.json`, разметка Product/Event/Article для поисковиков по-прежнему включается только после удаления `site.json → demoNotice`.
* **Преподаватели** (`redesign.json → teachers`, страница «Обучение»): идут сразу после «Четырёх шагов до семинара». Поля каждого: `first` (имя и отчество), `last` (фамилия), `role` (должность), `bio` (краткое описание — показывается под должностью; пока `null`), `photo` (путь к фото, `assets/teachers/<id>.webp`, 280×300; если `null` — показывается монограмма). Фото загружены для всех восьми преподавателей. ФИО и должности внесены со скриншота, присланного заказчиком. Без слоя доработок (`redesign:off`) страница остаётся прежней.
* **Первый экран главной со скролл-анимацией** (`redesign.json → jar`, кадры и спрайты в `assets/jar-arch/`): закреплённая сцена — зал с арками; на заставке баночка крупно по центру на светлом бежевом фоне (первый кадр зала закрыт светлым размытием, оно сходит по прокрутке и зал проявляется) и полоска «Листайте» (`cue`); по прокрутке баночка раскручивается и уходит на подиум, камера отъезжает к общему плану, затем встаёт герой. Старого тёмного вступления и экрана с лозунгом нет. Слои: ключевые кадры зала (`arch.desktop/mobile`; каменный шар запечён в них как статичная 3D-модель из камня горы) с картами глубины (`arch.depth`) и дорожкой камеры (`arch.cam`) — по ним WebGL-движок строит вид из любой точки прокрутки — и отдельные спрайты баночки без этикетки (`arch.jar.*.dir` и рамки `rects`) с маской надписей `arch.label` и силой чернил `arch.ink` (всё это пишет `tools/jar-render/apply_arch.py`). `arch.sphere.desktop|mobile` — где шар стоит в готовом кадре (центр x, центр y, диаметр — доли кадра): вокруг него встают орбиты логотипов. `arch.p` — положения кадров на пути прокрутки, `arch.panel` — панель «Почему выбирают Астрею?», `arch.heightVh` — длина сцены в высотах экрана. `jar.enabled = false` или `arch.enabled = false` — вернуть прежний герой с шаром и орбитами. Подробнее — README в корне («Плавность прокрутки») и `tools/jar-render/README.md`.
* **Фоновые вставки** (`redesign.json → backdrops`, картинки `assets/bg/`): макро-текстуры (крем-волны, мазок крема, молочный шёлк, линии и сетка, плёнки, пипетка, молекулы) за содержимым страниц. `enabled` — выключатель; `skipPages` — страницы без вставок (сейчас пусто); `skipClasses` — блоки без вставок (вступление, герой, бегущая строка); `skipClasses` — блоки, которые не трогаем; `textures` — описание текстур (файл `assets/bg/<имя>.webp`, место по умолчанию `pos`); `pages[<ключ страницы>]` — `variants` (несколько планов, которые по очереди достаются страницам с этим ключом — бренды, товары), либо прямо `top` (полоса за заголовком), `end` (полоса над подвалом), `mid` (на отдельном блоке: `sel` — «тег.класс#id», `n` — какой по счёту, `tex`, `pos`, `o`). `pos`: `tr tl br bl r l c t b full`; `o` — сила 3…10. Подробности и проверка — `tools/bg-render/README.md`, `npm run check:bg`.
