# Продающий слой «Путь к закупке» — плейбук

Слой включается флагом `data/redesign.json → extras.sales` (выключите флаг и пересоберите сайт — `node tools/build.js` — слой исчезнет целиком). Тексты и настройки — в `data/sales.json`, реплики Стеллы — в `data/stella/sales.json`, код — `js/sales.js`, `css/sales.css`, страница `start.html` (`src/pages/start.js`). Проверка — `npm run check:sales`, арена вариантов — `npm run arena:sales`.

## Главный принцип и честный ответ про «90 %»

Ни один сайт не может гарантировать, что 90 % посетителей захотят купить или записаться: в открытых отчётах о квизах и подборщиках конверсия колеблется примерно от 8 до 27 % в зависимости от отрасли и источника трафика, а для B2B-закупки обычно ниже. Поэтому слой делает другое:

1. **Убирает трение** — человек сразу видит следующий шаг, а не ищет его.
2. **Снижает тревогу** — «заявка ни к чему не обязывает», бесплатные базовые семинары, подбор ничего не отправляет без решения.
3. **Квалифицирует обращение** — менеджер получает не «позвоните мне», а задачи, цель, город и готовый план.
4. **Измеряет** — каждая заявка несёт метку источника; живые A/B-проверки показывают, что работает именно у вашей аудитории.

Чего слой **не делает** (и не будет делать по умолчанию): фальшивых таймеров и «акций», выдуманного дефицита, счётчиков «сейчас смотрят», выдуманных отзывов, стыдящих отказов, предзаполненных согласий. Это не только вопрос этики: такие приёмы подпадают под недобросовестную рекламу и вводящие в заблуждение практики (см. таблицу «Отклонено»).

### Ход для каждой страницы

**Оформление.** Ходы выполнены как «картотека»: прямоугольные карточки с цветной шиной сверху или слева, крупные засечные цифры (дата, процент, номер шага), календарная сетка, ступени. ## Психология — как она выражена (без манипуляций)

* **Взаимность.** Ценность до контакта: подборка, план, ориентир по скидке, расписание — всё видно без формы.
* **Микро-обязательства и цель-градиент.** «Шаг N из M», «До 10 % не хватает 50 000 ₽», «осталось N вопроса».
* **Эффект владения («IKEA») и незавершённое (Зейгарник).** Свой план, своя подборка, доска выбранных брендов; черновик сохраняется, на сайте остаётся «Открыть мой план».
* **Авторитет.** Только реальные преподаватели, офисы, события и факты со страниц «Компания» и «Партнёрам».
* **Якорение.** «До 15 %» с оговоркой «ориентировочно, подтверждает менеджер».
* **Прозрачность процесса.** «Что будет после запроса», «Как проходит запись», «Сейчас на связи» — человек знает, что произойдёт дальше.
* **Упрощение выбора.** Две двери на главной, готовые подборки, три шага у бренда.
* **Реальная срочность — только реальная.** Единственная «срочность» — настоящая дата семинара из расписания («через 3 дня»); никакого искусственного дефицита.

## Чем заменяем «90 %»: как считать

1. Подключите аналитику (`A.config.ymId`/`gtagId` в `js/core.js`) — события уже уходят в `dataLayer`: `sales_page`, `sales_bar_show/click/dismiss`, `sales_fork_view`, `sales_kits_view`, `sales_kit_add/show`, `sales_route_view`, `sales_timeline_view/city`, `sales_waitlist`, `sales_colleague`, `sales_ladder_cta`, `sales_region`, `sales_status`, `sales_search_rescue`, `sales_mod_click`, `sales_after_view`, `sales_click`, `sales_exp`, `sales_planner_view`, `plan_start`, `plan_step`, `plan_result`, `plan_cta`, `plan_signup`, `plan_list_add`, `plan_share`, `plan_restart`, `plan_ask_stella`, `form_submit` (с полем `src`).
2. В админке («Заявки») у каждой заявки есть «Источник», например: `p=product;via=bar;x=barDesktop:pill,ctaCopy:info` или `p=start;via=plan-main;plan=salon/acne.pigment/both/150`. По нему видно, какая страница, элемент и вариант проверки дали заявку.
3. Для эксперимента нужны сотни показов на вариант: сравнивайте долю заявок среди посетителей, видевших вариант (`sales_exp`). Когда решение очевидно — впишите `"fixed": "pill"` (или другой вариант) в `data/sales.json → experiments` и пересоберите.
4. Принудительно включить вариант для проверки: `?x=barDesktop:pill,ctaCopy:info`; оформление — `?v=planFlow:four,barStyle:bottom`.

## Данные-заглушки и что заменить перед запуском

* Мероприятия в `data/events.json` помечены `demo: true`, мест (`seats`) нет — блоки сами не показывают «осталось мест».
* Цен нет; пороги скидок 5/10/15 % при 50/150/300 тыс. ₽ — ориентировочные (из `data/site.json`), в текстах всегда с оговоркой «подтверждает менеджер».
* Отзывов, кейсов, документов и сертификатов на сайте нет. Когда появятся реальные — добавляйте в блок доверия (через `data/content.json`), а не в тексты слоя.
* Подключите реальную аналитику и (если нужно по закону) информирование о cookie. Сейчас сайт ничего не отправляет во внешние сервисы.

## Включение, выключение, откат

* Выключить слой: `extras.sales: false` в `data/redesign.json` → `node tools/build.js`. Страница `start.html`, блоки и панель исчезнут; заявки типа «plan» сервер продолжает принимать.
* **Плавающая панель внизу экрана выключена везде** (`data/sales.json → bar.enabled: false`); вернуть — `true` и `node tools/build.js`. Остальное (подборки, маршруты, «что дальше» после заявки) работает как раньше.
* Выключить панель на конкретной странице: добавьте её в `sales.barExclude`; убрать слой с страницы целиком — в `sales.exclude`.
* Откат к версии с общими блоками «Что дальше / Доверие» (до перестройки на ходы по страницам): ветка `pre-modules-rollback`. Полный откат к сайту до продающего слоя: ветка `pre-sales-rollback` (репозиторий `aassstrixx/astreya`).
* Вступление, герой с анимированным логотипом и орбитой брендов, шапка и подвал слоем **не затрагиваются**: на главной изменены только адресные кнопки в блоке «Для кого», а `check-sales` сверяет всю главную побайтно с версией до слоя.

## Арена

`npm run arena:sales` прогоняет в Chromium все сочетания оформления на телефоне 390×844 и компьютере 1280×860, меряет нажатия, объём текста, размеры кнопок, наложения на Стеллу/быструю связь, высоту панели/блоков и горизонтальную прокрутку. Веса условны — поэтому три расстановки; победитель обязан выиграть минимум две с отрывом ≥ 2 баллов, иначе остаётся текущий. Ходы по страницам арена только проверяет на вёрстку (блок на месте, нет горизонтальной прокрутки, кнопки ≥ 44 px): убедительность хода она не измеряет. `--apply` записывает победителей в `data/sales.json → variants`.

**Это не данные о конверсии.** Они появятся только из ваших заявок и аналитики.
