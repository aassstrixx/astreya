# Библиотека «живых» реплик Стеллы

Что отвечает Стелла, когда вопрос — **не про каталог и не про расписание**: о ней самой, «просто поболтать», странные просьбы, то, чего на сайте нет, тяжёлые темы, мини-справочник терминов, игры и расчёты. Работает **без ИИ и без интернета**, прямо в браузере; с включённым ИИ-режимом эти реплики остаются запасным ответом (кроме тем с пометкой `local` — они всегда отвечаются здесь, мгновенно).

Источник — только эти файлы. После правок: `node tools/build.js` (файлы попадают в `js/kb.js`), затем `node tools/check-stella.js`.

| Файл | Что внутри |
|---|---|
| `config.json` | общие настройки: «лестница» запасных ответов, «мостики» к делу, загадки, факты, шутки, ответы на смайлики, словарь для распознавания раскладки |
| `persona.json` | о самой Стелле: имя, возраст, кто создал, как работает, чувства, «ты настоящая?», любимое, недостатки, комплименты и грубости, общая ступень «вопрос о тебе» |
| `chat.json` | светская беседа и служебные реплики: «как дела», «подожди», «ок», «повтори», «объясни проще», «давай сначала», настроение, игры (монетка, кубик, загадка, число, «да или нет»), дни до праздников, дата «через N дней», запоминание имени |
| `scope.json` | не по теме сайта (погода, политика, финансы, кино, рецепты, код, домашние задания…) и **чего на сайте нет** (возврат, оплата, пробники, вакансии, соцсети, маркетплейсы, «веган/органик»…) |
| `safety.json` | тяжёлые и опасные темы: кризис (112), экстренные симптомы, реакция кожи, грубость, «взлом» инструкций, незаконное, личные данные и ссылки в чате |
| `glossary.json` | мини-справочник терминов косметологии (SPF, ретинол, пилинг, комедоны…) — общая справка, не рекомендация |
| `english.json` | краткие ответы по-английски (привет, цена, каталог, контакты…) |

## Принципы (не нарушать)

* **Честность.** Никаких цен, наличия, сроков, сертификатов, «отзывов», обещаний и медицинских советов. Чего нет на сайте — так и говорим и ведём к менеджеру (`{phone}`, `{hours}`, `{email}` подставляются из данных сайта).
* Стелла — **программа**, а не человек; она не называет модель ИИ и не выдумывает о себе фактов (кто именно написал код — «не знаю»).
* Тяжёлое (кризис, экстренные симптомы) — коротко, участливо, **без «мостиков» к продажам**; номер 112.
* Определения — нейтральные и общеизвестные, всегда с оговоркой «подбор ухода определяет специалист».
* Реплики короткие (≤ 700 знаков), тёплые, без восклицательных «продающих» оборотов.

## Формат темы

```json
{ "id": "age", "g": "persona", "stage": "mid", "local": false, "b": false, "prio": 0,
  "q": ["сколько|скока лет|годиков !компани", "возраст @you"],
  "a": ["вариант 1", "вариант 2", "вариант 3"],
  "chips": ["кнопка 1", "кнопка 2"], "act": ["callback"], "links": [["catalog.html?task=sun", "Фотозащита"]] }
```

* `id` — латиница/цифры/`_`, уникальный. `g` — группа (`persona`, `chat`, `fun`, `scope`, `glossary`, `business`, `safety`): по ней берутся «мостик» и кнопки по умолчанию.
* `a` — **варианты ответа**. Повторный вопрос получает следующий вариант; когда варианты кончились — тот же текст с «Вы уже спрашивали — отвечу иначе». Чем больше вариантов (3–5), тем «живее».
* `b` — «мостик» к делу вторым сообщением: свой список (`["…"]`), `false` (без мостика) или не задан (общий по группе, примерно в каждом втором ответе). `"bridge": "always"` — всегда.
* `chips` — быстрые кнопки; `act` — `callback` (заказать звонок), `partner`, `request`, `ask` (вопрос менеджеру); `links` — `[страница, подпись]` (проверяются на существование, `?task=` и `?cat=` — по данным каталога).
* `local: true` — отвечать здесь **даже при включённом ИИ** (безопасность, игры, расчёты, служебные «ок / повтори»). Без неё при включённом ИИ вопрос уходит модели, а эта реплика остаётся запасной.
* `stage` — когда проверять тему: `early` — до всего (безопасность, определения терминов, игры, расчёты); `mid` (по умолчанию) — после светских реплик и контекста диалога, **раньше общих «намерений» сайта** (чтобы «договорились» не принималось за «договор»); `pre` — после намерений сайта; `post` — после поиска по материалам сайта; `en` — только для английского текста.
* `prio` — прибавка к баллу при выборе между подходящими темами (например, `either` выигрывает у «кино» в «выбери: кино или театр»).
* `rx` — дополнительные регулярные выражения по сырому тексту (номер карты, ссылки).
* `fn` — расчёт в коде: `pickval` (+`vals`), `randnum`, `either`, `countdown` (+`a0`), `dayplus`, `nameSet`, `nameGet` (+`a0`), `repeat`, `clarify`, `riddle`, `fact`, `joke`, `social`. `reset: true` — сбросить контекст диалога, `repeat: true` — «ещё» повторяет тему.
* Подстановки в тексте: `{hello}` (по времени суток), `{phone}`, `{hours}`, `{email}`, `{company}`, `{adv}` (преимущества из данных сайта), `{date}`, `{weekday}`, `{time}`, `{,nm}` (", Имя", если назвались), `{nm}`, `{city}`; расчётные — `{v}`, `{days}`, `{dword}`, `{what}`, `{n}`, `{a}`, `{b}`, `{q}`, `{t}`.

## Правила `q`

Тема срабатывает, если подошло **любое** правило. Правило — слова через пробел, **все** должны найтись во фразе (в любом порядке):

* `слово|другое|третье` — любое из вариантов; слово длиннее 4 букв сравнивается **по началу и по основе** (`расскаж` найдёт «расскажи», «расскажите»; падежи и числа учитываются), а длиной до 4 букв — **целиком** (`кот` не найдёт «котик» — перечислите формы);
* `как_дела` — фраза (подчёркивание = пробел); `=да` — только такое слово целиком; `!слово` — слова не должно быть;
* `ты` / `вы` / `@you` — любое местоимение второго лица (ты, тебя, тебе, твой, вы, вас…); `я` / `мы` / `@me` — первого лица; `@def` — «что такое / что значит / объясни…» (для справочника), `@tell` — «расскажи про…» (не срабатывает, если назван товар или бренд из каталога);
* `*…` в начале — **ключевое** правило: слово может стоять где угодно (баллы ниже, для длинных фраз ≤ 16 слов); `~…` — «слабое»: проверяется последним, когда ничего больше не нашлось.

Обычное правило должно «покрывать» не меньше половины значимых слов вопроса (местоимения, предлоги и «как / что / какой» не считаются) — поэтому длинный вопрос о другом тему не захватит.

## «Лестница» запасных ответов

Если ничего не подошло, ответ зависит от **вида** фразы (`config.json → ladder`): вопрос, просьба-задание («напиши…»), утверждение, одно слово (повторяется в «»), случайные буквы, «возможно, вы имели в виду…»; после трёх промахов подряд — прямое предложение позвать менеджера (`escalate`). Отдельно: английский, украинский и другие письменности. Каждая ступень — несколько вариантов, поэтому отказ не звучит одинаково.

## Как добавить тему

1. Допишите тему в нужный файл (`id`, `q`, 3–5 вариантов `a`).
2. Добавьте 3–5 живых формулировок в `tools/stella-cases.js` — `T('id', 'фраза', …)`. Если фраза из сайта не должна попадать в тему — `NO('фраза')`.
3. `node tools/build.js && node tools/check-stella.js`. Проверка разбирает данные (ссылки, подстановки, повторы, запрещённое), прогоняет все формулировки и **все названия товаров, брендов, задач, семинаров, FAQ и новостей** (они не должны попадать в реплики), а также диалоги: загадка, имя, «повтори», дни до праздника, кубик, раскладка, английский, смайлики, лестница отказов.
