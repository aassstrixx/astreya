# Библиотека «живых» реплик Стеллы

Что отвечает Стелла, когда вопрос — **не про каталог и не про расписание**: о ней самой, «просто поболтать», странные просьбы, то, чего на сайте нет, тяжёлые темы, мини-справочник терминов, игры и расчёты. Работает **без ИИ и без интернета**, прямо в браузере; с включённым ИИ-режимом эти реплики остаются запасным ответом (кроме тем с пометкой `local` — они всегда отвечаются здесь, мгновенно).

Источник — только эти файлы. После правок: `node tools/build.js` (файлы попадают в `js/kb.js`), затем `node tools/check-stella.js`.

| Файл | Что внутри |
|---|---|
| `config.json` | общие настройки: «лестница» запасных ответов, «мостики» к делу, загадки, факты, шутки, ответы на смайлики, словарь для распознавания раскладки |
| `persona.json` | о самой Стелле: имя, возраст, кто создал, как работает, чувства, «ты настоящая?», любимое, недостатки, комплименты и грубости, общая ступень «вопрос о тебе» |
| `chat.json` | светская беседа и служебные реплики: «как дела», «подожди», «ок», «повтори», «объясни проще», «давай сначала», настроение, игры (монетка, кубик, загадка, число, «да или нет»), дни до праздников, дата «через N дней», запоминание имени |
| `scope.json` | не по теме сайта (погода, политика, финансы, кино, рецепты, код, домашние задания…) и **чего на сайте нет** (возврат, оплата, пробники, вакансии, соцсети, маркетплейсы, «веган/органик»…) |
| `safety.json` | тяжёлые и опасные темы: кризис (112), экстренные симптомы, реакция кожи, грубость, «взлом» инструкций, незаконное, личные данные и ссылки в чате |
| `glossary.json` | мини-справочник терминов косметологии (SPF, ретинол, пилинг, комедоны…) — общая справка, не рекомендация |
| `english.json` | краткие ответы по-английски (привет, цена, каталог, контакты…) |
| `daily.json` | бытовое («хочу покушать», «хочу кофе», «хочу пить», «не выспалась», «много работы», «была в зале»…): отвечает по-человечески и мягким мостиком возвращает к каталогу и косметологии; без советов по здоровью |
| `sales.json` | помощь с первым шагом (продающий слой `extras.sales`): «с чего начать закупки», «что такое «Старт со Стеллой»», «хочу купить» (корзины нет, заказ через менеджера), «надо подумать» (без давления), подлинность продукции, «мой план» без плана. Тексты честные: никакого дефицита, давления временем, отзывов и обещаний; дальше — подбор, бесплатные базовые семинары, звонок менеджера. Пересказ **сохранённого** плана делает «мозг» (`planAnswer` в `js/assistant-brain.js`) |
| `voice.json` | **«Голос Стеллы»**: как она говорит в ответах без ИИ — приветствия панели по странице и времени суток и пулы реплик (товар, бренд, задача, расписание, скидки, контакты, партнёрство, компания, новости, сравнение, «спасибо», «да/нет»…) — см. раздел «Голос Стеллы» ниже |
| `guide.json` | **не реплики, а настройки «навигатора»** (страницы, что подсвечивать, экскурсии, сравнение, подсказки, блоки на страницах) — см. ниже |

## Принципы (не нарушать)

* **Честность.** Никаких цен, наличия, сроков, сертификатов, «отзывов», обещаний и медицинских советов. Чего нет на сайте — так и говорим и ведём к менеджеру (`{phone}`, `{hours}`, `{email}` подставляются из данных сайта).
* Стелла — **программа**, а не человек; она не называет модель ИИ и не выдумывает о себе фактов (кто именно написал код — «не знаю»).
* Тяжёлое (кризис, экстренные симптомы) — коротко, участливо, **без «мостиков» к продажам**; номер 112.
* Определения — нейтральные и общеизвестные, всегда с оговоркой «подбор ухода определяет специалист».
* Реплики короткие (≤ 700 знаков), тёплые, без восклицательных «продающих» оборотов.

## Формат темы

```json
{ "id": "age", "g": "persona", "stage": "mid", "local": false, "b": false, "prio": 0,
  "q": ["сколько|скока лет|годиков !компани", "возраст @you"],
  "a": ["вариант 1", "вариант 2", "вариант 3"],
  "chips": ["кнопка 1", "кнопка 2"], "act": ["callback"], "links": [["catalog.html?task=sun", "Фотозащита"]] }
```

* `id` — латиница/цифры/`_`, уникальный. `g` — группа (`persona`, `chat`, `fun`, `scope`, `glossary`, `business`, `safety`): по ней берутся «мостик» и кнопки по умолчанию.
* `a` — **варианты ответа**. Повторный вопрос получает следующий вариант; когда варианты кончились — тот же текст с «Вы уже спрашивали — отвечу иначе». Чем больше вариантов (3–5), тем «живее».
* `b` — «мостик» к делу вторым сообщением: свой список (`["…"]`), `false` (без мостика) или не задан (общий по группе, примерно в каждом втором ответе). `"bridge": "always"` — всегда.
* `chips` — быстрые кнопки; `act` — `callback` (заказать звонок), `partner`, `request`, `ask` (вопрос менеджеру); `links` — `[страница, подпись]` (проверяются на существование, `?task=` и `?cat=` — по данным каталога).
* `local: true` — отвечать здесь **даже при включённом ИИ** (безопасность, игры, расчёты, служебные «ок / повтори»). Без неё при включённом ИИ вопрос уходит модели, а эта реплика остаётся запасной.
* `stage` — когда проверять тему: `early` — до всего (безопасность, определения терминов, игры, расчёты); `mid` (по умолчанию) — после светских реплик и контекста диалога, **раньше общих «намерений» сайта** (чтобы «договорились» не принималось за «договор»); `pre` — после намерений сайта; `post` — после поиска по материалам сайта; `en` — только для английского текста.
* `prio` — прибавка к баллу при выборе между подходящими темами (например, `either` выигрывает у «кино» в «выбери: кино или театр»).
* `rx` — дополнительные регулярные выражения по сырому тексту (номер карты, ссылки).
* `fn` — расчёт в коде: `pickval` (+`vals`), `randnum`, `either`, `countdown` (+`a0`), `dayplus`, `nameSet`, `nameGet` (+`a0`), `repeat`, `clarify`, `riddle`, `fact`, `joke`, `social`. `reset: true` — сбросить контекст диалога, `repeat: true` — «ещё» повторяет тему.
* Подстановки в тексте: `{hello}` (по времени суток), `{phone}`, `{hours}`, `{email}`, `{company}`, `{adv}` (преимущества из данных сайта), `{date}`, `{weekday}`, `{time}`, `{,nm}` (", Имя", если назвались), `{nm}`, `{city}`; расчётные — `{v}`, `{days}`, `{dword}`, `{what}`, `{n}`, `{a}`, `{b}`, `{q}`, `{t}`.

## Правила `q`

Тема срабатывает, если подошло **любое** правило. Правило — слова через пробел, **все** должны найтись во фразе (в любом порядке):

* `слово|другое|третье` — любое из вариантов; слово длиннее 4 букв сравнивается **по началу и по основе** (`расскаж` найдёт «расскажи», «расскажите»; падежи и числа учитываются), а длиной до 4 букв — **целиком** (`кот` не найдёт «котик» — перечислите формы);
* `как_дела` — фраза (подчёркивание = пробел); `=да` — только такое слово целиком; `!слово` — слова не должно быть;
* `ты` / `вы` / `@you` — любое местоимение второго лица (ты, тебя, тебе, твой, вы, вас…); `я` / `мы` / `@me` — первого лица; `@def` — «что такое / что значит / объясни…» (для справочника), `@tell` — «расскажи про…» (не срабатывает, если назван товар или бренд из каталога);
* `*…` в начале — **ключевое** правило: слово может стоять где угодно (баллы ниже, для длинных фраз ≤ 16 слов); `~…` — «слабое»: проверяется последним, когда ничего больше не нашлось.

Обычное правило должно «покрывать» не меньше половины значимых слов вопроса (местоимения, предлоги и «как / что / какой» не считаются) — поэтому длинный вопрос о другом тему не захватит.

## «Лестница» запасных ответов

Если ничего не подошло, ответ зависит от **вида** фразы (`config.json → ladder`): вопрос, просьба-задание («напиши…»), утверждение, одно слово (повторяется в «»), случайные буквы, «возможно, вы имели в виду…»; после трёх промахов подряд — прямое предложение позвать менеджера (`escalate`). Отдельно: английский, украинский и другие письменности. Каждая ступень — несколько вариантов, поэтому отказ не звучит одинаково.

## Как добавить тему

1. Допишите тему в нужный файл (`id`, `q`, 3–5 вариантов `a`).
2. Добавьте 3–5 живых формулировок в `tools/stella-cases.js` — `T('id', 'фраза', …)`. Если фраза из сайта не должна попадать в тему — `NO('фраза')`.
3. `node tools/build.js && node tools/check-stella.js`. Проверка разбирает данные (ссылки, подстановки, повторы, запрещённое), прогоняет все формулировки и **все названия товаров, брендов, задач, семинаров, FAQ и новостей** (они не должны попадать в реплики), а также диалоги: загадка, имя, «повтори», дни до праздника, кубик, раскладка, английский, смайлики, лестница отказов.


## guide.json — настройки навигатора

Формат: `{"guide": {pages, targets, tours, compare, nudge, entry, arena}}`; файл **без `topics`** (реплики не затрагивает). Сборка кладёт его в `js/data.js` (`ASTREYA_DATA.guide`), если включены `assistant` и `navigator`. После правок: `node tools/build.js`, затем `node tools/check-navigator.js`.

* `pages` — страницы, куда Стелла может отвести: `{id, href, label, syn}`; `syn` — слова-начала для распознавания («партнёр» найдёт «партнёрам», «партнёров»). Открыть можно только эти страницы и страницы товаров/брендов/мероприятий из данных.
* `targets` — что можно **подсветить**: по ключам страниц (`*` — на любой): `{id, sel, label, say, syn}`; `sel` — CSS-селектор (берётся первый видимый элемент), `say` — что Стелла говорит. Если элемента нет на экране (например, спрятан в меню на телефоне), шаг экскурсии пропускается.
* `tours` — экскурсии: `{id, title, syn, steps: [{page, target, say, optional, next}]}`; `page` — ключ страницы (`any` — любая). Шаг на странице-«листе» (товар, мероприятие) ждёт, пока её откроют. `next: {l, click, link}` — «Далее» с настоящим нажатием Стеллы на найденную цель (ссылку меню, карточку; `link` — вложенный селектор) — так экскурсия сама переходит на другую страницу. Состояние живёт в `sessionStorage` ≈ 1 минуту (только на время перехода). Запускается только по просьбе посетителя.
  * **Экскурсия `site` («Покажи сайт») — со «своим курсором».** `start: "first"` (всегда с главной), `groups` — девять этапов (индикатор «2 из 9»; в шагах `g` — номер этапа), `view` — прокрутить к блоку («первый экран»), `chrome` — цель в шапке (шапка закрепляется, на узких экранах сам раскрывается ящик меню), `sel` — свой CSS-селектор прямо в шаге (если цели нет в `targets`). В каждом разделе несколько шагов: показываем разные места страницы и действия, а не одну случайную мелочь.
  * **Действия `acts`** — маленький сценарий, который Стелла выполняет на глазах у посетителя (шаг без `acts` просто подсвечивает цель и подводит к ней курсор): `{point: sel, at?, hold?}` — курсор плывёт и «замирает» на элементе; `{click: sel, undo?, after?}` — плывёт, нажимает (круги от нажатия) и нажимает по-настоящему; `{type: sel, text}` — нажимает на поле и **печатает по буквам** (≈ 250–360 мс на букву; поле и набранное подсвечены синим; `@prod` — первое слово названия первого товара); `{choose: sel, value?}` — нажимает на список, **раскрывается меню** (пункты те же, выбор настоящий), курсор скользит по пунктам и выбирает; `{drag: sel, to: '@tier1'|число}` — берёт ползунок и неспешно тянет; `{report: count|calc|tiers|visible|text, …}` — считывает то, что реально стало на странице (в `vars`); `{say: 1}` — заменяет текст карточки итоговым `say` с подстановкой `{q}`, `{n}`, `{total}`, `{task}`, `{city}`, `{fm}`, `{tab}`, `{title}`, `{sum}`, `{tier}`, `{tiers}`; `{wait: мс}`, `{reset: 1}` (вернуть каталог в исходное); `{fill: форма}` — заполняет заявку «для примера»: поле за полем курсор нажимает и печатает придуманные данные (имя, телефон `+7 (9XX) 555-01-NN`, почта `…@example.com`, город, организация, комментарий из короткого списка по типу формы; специализацию выбирает через раскрывающееся меню, `choose` с `value: "@rand"`, `stay`, `fast`). Согласие не отмечается, форма не отправляется, при выходе и на следующем шаге всё стирается; на телефоне рамка переходит от поля к полю. Пулы данных — `DEMO` в `js/guide.js`. Пока идёт сценарий, в карточке стоит `pre`; потом — итоговый `say`. Всё, что сценарий изменил (запрос, фильтры, вкладки, ползунок, отметки сравнения), **возвращается** при следующем шаге и при выходе.
  * `offer: {l, do: "cmp-demo", say}` — «попробовать»: курсор сам отмечает два товара для сравнения — только по нажатию посетителя («Показать на примере»), потом отметки снимаются. `final` — финальный шаг (каталог / «Старт со Стеллой» / спросить Стеллу).
  * **Переходы между разделами.** В `pages[]` у раздела есть `nav` (CSS-селектор пункта меню, ссылки в шапке или подвале) и `go` (что Стелла говорит по дороге). На последнем шаге раздела она подсвечивает этот пункт, плывёт к нему курсором и **нажимает** — открывается следующая страница, экскурсия продолжается. Если пункта нет (или он не сработал) — переходит сама. «Мостиков» вида «Идём дальше» больше нет: каждая реплика говорит о деле.
  * **Страница закреплена.** Пока экскурсия идёт, колесо, палец, клавиши (стрелки, PageUp/PageDown, Home/End) и ползунок прокрутки не двигают страницу: подсвеченный абзац и Стелла стоят на месте. Листает только Стелла (плавно, до начала показа). Если фильтр сделал страницу короче и она «подтянулась» — закрепление сдвигается вместе с ней. Всё снимается на «Пропустить», в конце экскурсии и при выходе.
  * **Рамка и карточка.** Рамка подсветки всегда обходит блок **целиком** (не обрезается), поэтому для больших разделов в шаге берут конкретный кусок: `sel` — что подсветить, `msel` — другой селектор для телефона (узкие экраны, где блоки вытянуты вниз), `at` — на какой высоте экрана поставить блок (доля высоты), `above: true` — карточка Стеллы над блоком (чтобы не закрывать то, что меняется под ним). Страница прокручивается так, чтобы блок и карточка помещались вместе; карточка встаёт снизу, сверху, а если места нет — сбоку. Сценарии (`point`) показывают только то, что внутри рамки. Прокрутка между частями страницы — своя плавная (с разгоном и торможением, длительность зависит от расстояния), пока страница едет, рамка «приклеена» к блоку, а карточка стоит и потом плавно переезжает.
  * **Темп.** Курсор, набор текста и меню рассчитаны на «человеческую» скорость: глаза успевают. Ускоряется только в тестах (`window.ASTREYA_MOTION_SPEED`). Анимации не отключаются «спокойным режимом».
* `compare` — `plate` (текст кнопки на плашке — «Попросить Стеллу рассказать»), `plateShort` (на телефоне), `request` / `requestOne` (фраза, которую Стелла «получает» от кнопки; `{names}` — названия), `max` (до скольких товаров), `template` (формат ответа: `sections` · `verdict` · `cards` · `lines` · `brief` — выбрала арена), `plateStyle` (`full` · `compact` · `stacked`).
* `nudge` — **всплывающее окно Стеллы: только на главной** (`pages: ["home"]`; на остальных страницах окон нет — там блок `entry` и кнопка Стеллы). Один раз за сессию, когда посетитель дошёл до самой страницы (вступление закончилось). `welcome`: `title` («Добро пожаловать…»), `lead` («Я Стелла, могу»), `can` — фразы, которые по кругу сменяют друг друга (`rotateSec`), `chips`, `delaySec`, `showSec`; `layout` (`bubble` · `pill` · `card`); `compareIdleSec` — через сколько секунд после выбора товаров мигнёт плашка сравнения (без окна).
* `entry` — блок «Не знаете, что выбрать?» на странице: `style` (`strip` · `slim` · `card`), `pages[ключ]` = `{anchor (селектор), pos (after · before · beforeSection), title, text, chips}`. `title` и `text` могут быть **списком вариантов** — при каждом заходе показывается один; так же `say` у целей подсветки (`targets`).
* `arena` — что выбрала арена (`npm run arena:stella`); править руками можно, но следующий прогон с `--apply` перезапишет.

Правила, которые не нарушать: тексты без цен, наличия, сроков, обещаний и давления («только сегодня», «лучшее»); ссылки только на этот сайт; говорить **своими словами** (не копировать заголовки и абзацы страниц) и в женском роде.

## Голос Стеллы (`voice.json`)

Всё, что Стелла отвечает **без ИИ** по данным сайта (товар, бренд, задача, мероприятия, скидка, контакты, партнёрство, компания, новости, сравнение, приветствие, «спасибо»), собирается из **её слов**: факты берутся из данных, а оборот речи — из пулов этого файла. Абзацы со страниц (описания товаров и брендов, «логика ухода» задач, «о компании», шаги партнёрства) **не вставляются** — их пересказывает сама Стелла.

* `welcome` — приветствие панели: `default`, `product`, `brand`, `event`, `catalog`, `training`, `partners` (по странице; для товара — `{name}`, для мероприятия — `{title}`), `nav` и `ai` — добавки, если включены навигатор и ИИ. Подстановка `{hello}` — «Доброе утро / Добрый день…».
* `pools` — списки вариантов по ключам (`greet`, `thanks`, `product.open`, `product.follow`, `brand.profile`, `task.open`, `events.list`, `discount.lead`, `partner.how`, `about.text`, `compare.open`, `nav.open`, `price`, `avail`…). **Варианты идут по кругу** (счётчик в состоянии диалога): повторный вопрос получает следующую фразу. Ключ `*.follow` — **встречный вопрос**: движок запоминает его (`pending`) и подхватывает «да» — оформить запрос по товару, записаться на семинар, открыть форму партнёра, заказать звонок, запустить экскурсию.
* Подстановки: общие (`{hello}`, `{phone}`, `{hours}`, `{,nm}`, `{city}`…) и по месту: `{name}`, `{brand}`, `{cat}`, `{kind}`, `{tasks}`, `{actives}`, `{country}`, `{n}`/`{nword}`, `{label}`, `{brands}`, `{cats}`, `{ctx}`, `{date}`, `{days}`, `{fm}`, `{title}`, `{tiers}`, `{who}`, `{names}`, `{titles}`.
* Правила: женский род («нашла», «подобрала»); никаких цен, наличия, сроков и давления; по два варианта и больше; не больше 700 знаков; в ответах про товары/бренды/задачи/компанию — **ни одного дословного куска страниц** (проверка пяти слов подряд). Нет файла или пула — движок берёт запасной текст из кода, как раньше.
* Проверки: `node tools/check-stella.js` (раздел «Голос Стеллы»), `node tools/check-assistant.js` (раздел 11).
