# Первый экран главной: зал с арками, баночка и живой шар (`assets/jar-arch`)

Закреплённая сцена со скролл-анимацией (`#arch-story`, `js/jar.js`, `js/sphere.js`, `css/home-arch.css`). Старого тёмного вступления с баночкой и экрана с лозунгом больше нет — вместе со всем его конвейером кадров.
Сцена собирается из трёх независимых слоёв (чтобы баночка была резкой, не двоилась и не проходила сквозь фон, а шар в прокрутке стоял на месте):

| слой | что это | чем делается | где лежит |
|---|---|---|---|
| зал | кадры без баночки и без шара: стена из светлого камня с аркой и нишей, каменный знак «Астреи», комната со стеллажом слева, олива, подиум, камни, пол | `hall_story.py anim … --layer bg` → `encode_arch.py` | `assets/jar-arch/d`, `m` (полные), `dm`, `mm` (лёгкие, с запечёнными промежуточными) |
| баночка | отдельный спрайт на каждый кадр сценария: прозрачный WebP, отрендерен с передискретизацией ×1,6 и обрезан по своей рамке | `hall_story.py anim … --layer jar` → `encode_jar.py` | `assets/jar-arch/j`, `jm` + рамки в `data/redesign.json → jar.arch.jar.*.rects` |
| шар | живой WebGL-слой (`js/sphere.js`): карта цвета и карта нормалей травертина, свет считается на лету | `bake_sphere.py` | `assets/jar-arch/sphere-a.webp`, `sphere-n.webp`; запасная картинка `stone-sphere.webp` |

Сцена целиком в метрах (Blender / Cycles). Баночка — настоящая модель из `lumiere_scene.py` (крышка — тёмно-синий лак), увеличена вдвое; этикетка («Астрея», `make_label.py` → `label.png`) всё время смотрит на камеру.
Материалы камня — `tools/showroom-assets/materials.py`, упаковки на стеллаже — `tools/showroom-assets/packs.py`, камни — `tools/decor/rocks.py`, знак «Астреи» (гора с острыми кончиками и серп) — `tools/decor/stone_logo.py`.
Камни, гора и шар **не достраиваются** по ходу анимации: всё стоит на месте с первого кадра, меняются только камера (мягкий наезд-отъезд) и баночка.

## Сюжет и камера

* Прогресс `p` сцены от 0 до 1 = прокрутка закреплённой части. Заставка (p = 0): баночка крупно по центру зала, внизу полоска «Листайте». Дальше камера отъезжает, баночка опускается по дуге `JAR_WAY` и уходит на подиум, в нише разгорается свет;
  с `HOLD` = 0,90 сцена «держит» последний кадр (покой героя), поверх встаёт текст, орбиты логотипов и панель «Почему выбирают Астрею?».
* **Шар в прокрутке не участвует.** Камера снята «наездом с отъездом»: она едет по лучу к шару, а фокусное меняется во столько же раз (`cam_state`, `K0` = 0,88 — наезд мягкий), и сдвиг кадра (`shift_x/y`) подбирается численно (`place_camera`), так что центр и размер шара в кадре
  одни и те же на всех кадрах (проверка — `track`, поле `sphere`). На сайте шар — живой слой, он стоит на месте, а зал вокруг почти не «плывёт»: движется только баночка. У телефона свой ракурс (`CAM_END_P`): арка и подиум в нижней части кадра, сверху место под заголовок.
* Баночка всегда над шаром (на подиуме её не закрывает даже край шара), орбиты, текст и логотипы — над баночкой.

## Команды

```bash
pip install bpy pillow numpy opencv-python-headless            # Python 3.11
python3 hall_story.py still 59 /tmp/f.png --layer all --sphere --res 1600x900 --samples 26   # один кадр целиком (--sphere рисует шар для просмотра; на сайте он живой)
python3 hall_story.py track /tmp/track-d.json --total 60 [--portrait]       # рамки баночки по кадрам и положение шара (быстро: без рендера)
python3 hall_story.py anim 0 59 /tmp/bg_d --stride 6 --samples 16 --total 60      # зал, черновик: каждый 6-й кадр (оценить сюжет за ~20 мин)
python3 hall_story.py anim 0 59 /tmp/bg_d --samples 16 --total 60                 # зал, десктоп 1920×1080 (≈1,8 мин/кадр на 4 ядрах); готовые кадры пропускаются, поэтому добирает остальные
python3 hall_story.py anim 0 59 /tmp/jar_d --layer jar --ss 1.6 --samples 24 --total 60   # спрайты баночки (≈40 с/кадр)
python3 hall_story.py anim 0 59 /tmp/bg_p  --samples 16 --total 60 --portrait             # то же для телефона (900×1600)
python3 hall_story.py anim 0 59 /tmp/jar_p --layer jar --ss 1.6 --samples 24 --total 60 --portrait
python3 bake_sphere.py                                                      # карты шара → assets/jar-arch/sphere-a.webp, sphere-n.webp
python3 encode_arch.py /tmp/bg_d ../../assets/jar-arch/d --lite ../../assets/jar-arch/dm --size 1920x1080 --lite-size 1280x720 --end 1.0
python3 encode_arch.py /tmp/bg_p ../../assets/jar-arch/m --lite ../../assets/jar-arch/mm --size 900x1600 --lite-size 600x1067 --end 1.0
python3 encode_jar.py /tmp/jar_d ../../assets/jar-arch/j                     # спрайты → прозрачный WebP (для телефона — jm)
python3 apply_arch.py --p ../../assets/jar-arch/p-d.json --track-d /tmp/track-d.json --track-p /tmp/track-p.json   # число кадров, положения p / pb, рамки и положение шара → data/redesign.json → jar
```

`--total` должен совпадать с `data/redesign.json → jar.arch.frames` (60). `encode_arch.py` кладёт рядом с набором `p-<имя>.json` (положения кадров на прокрутке; `--end` — на какой доле пути лежит последний кадр, после него сцена держит кадр),
лёгкий набор строится запеканием промежуточного кадра между каждой парой полных (оба кадра сдвигаются к середине по оптическому потоку DIS и смешиваются), в браузере он показывается, пока картинка движется. Лёгкое зерно при записи (`--grain`) убирает «полосы» на плавных
градиентах стены; `--sharpen` возвращает резкость мелкого камня после шумоподавления Cycles. Фон резкий: размытия глубины резкости нет (DOF выключен), 16 проходов + OIDN, кадры 1920×1080.
Выключить сцену на сайте: `data/redesign.json → jar.enabled = false` или `jar.arch.enabled = false` (останется прежний герой с шаром и орбитами), затем `node tools/build.js`.

## Проверка пути

Путь баночки задан точками `JAR_WAY` (в метрах, основание баночки) и не должен проходить сквозь шар, плиты «горы», подиум и камни. Проверять так: загрузить сцену (`build_scene`), на каждом кадре взять центр баночки,
найти расстояние до сетки всех твёрдых объектов (`BVHTree.find_nearest`) и до шара; минимум должен быть больше радиуса баночки (≈ 0,11 м), кроме последних кадров, где она ставится на подиум (расстояние до столешницы там равно полувысоте баночки).
Для телефона точки свои (`JAR_WAY[True]`): путь идёт почти по центру кадра. Камни у подиума (`build_decor`) стоят справа от подхода, чтобы освободить путь.

## Стеллаж в комнате слева

Вместо дивана — стеллаж из светлого камня (`build_shelf`): цоколь, две стойки и четыре полки, на каждой по три упаковки (флаконы, баночки, помпы, пипетки, тубы, коробка — `SHELF_ITEMS`), стоит у задней стены комнаты за левой аркой
(в кадр попадает узкая полоса стены между x ≈ −2,16 и −1,5 м, поэтому стеллаж узкий). Упаковки — те же макеты без текста, что в шоуруме каталога.
