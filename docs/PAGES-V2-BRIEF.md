# Страницы v2 — общее задание (15.11.2026)

Заказчик: остальные вкладки сайта переделываются в новый формат — «чтобы от старой версии не осталось ничего, использовать исключительно новое». Полная свобода дизайнерских решений и идей, но с соблюдением всего, что было сказано раньше. Этот файл — единые правила для всех, кто делает страницы.

## 0. Что нельзя нарушать (слова заказчика)

- «Не выполняй необратимые действия без отдельного подтверждения: удаление исходных данных, изменение истории Git, публикация в production, покупка ресурсов, платные генерации сверх доступных лимитов и передача конфиденциальных данных сторонним сервисам. Перед изменениями сохраняй резервную копию.»
- «Не ломай существующие рабочие функции. Не удаляй существующие интерактивные возможности. Не меняй бизнес-логику ради визуального эффекта.»
- «Не выдумывай реальные отзывы и результаты опросов. Разделяй подтверждённые пользовательские данные, экспертные гипотезы и результаты собственного тестирования.»
- Без кнопки «Без анимации»; механику `prefers-reduced-motion` не трогать (но каждая анимация обязана её уважать).
- Реализм, текстуры, гамма, тени, сочетание цветов — как на уже переделанных страницах (главная, каталог, бренды, обучение). Качество работы и удобство использования — наравне с внешним видом.

«Новое» значит: свой композиционный замысел страницы, своя сцена/материал, никаких старых «карточек в сетке на кремовом фоне» и старых героев-врезок. Но **содержание** (тексты, даты, адреса, цены/условия, ссылки, формы, события, товары) берётся из данных и сохраняется целиком; ничего не выдумывается (там, где данных нет, остаётся прежнее «Уточняется — запросите у менеджера»).

## 1. Эталоны, с которых начинать (читать до работы)

- Дизайн-система: `docs/DESIGN-SYSTEM.md` (раздел «Единый цвет и текстуры сцен»), `css/system.css`, `css/academy.css`, `css/brands-wall.css`, `css/gallery.css`, `css/house.css` — как они сделаны.
- Цвет сцен: hue 83–89°, a ≈ 0,3–1,1, b ≈ 8–13, контраст L ±17–20; фон страниц — молочно-тёплый камень, акценты — тёмно-синий (кнопки «Стать партнёром»), серебро/латунь точечно. Шапка и подвал — уже в новом виде (`system.css`), не менять.
- Готовые изображения сцен: `assets/academy/*` (зал, галерея, журнал), `assets/brands/*`, `assets/showroom/*` и `assets/decor/*` (слои каталога: стены, подиумы, ниши), `assets/products/*` и спрайты упаковок `pack-*`, `assets/house*`/`assets/jar-arch/*`, фото `assets/photos/*`, преподаватели `assets/teachers/*`. Сначала собирайте композицию из готового (слои, спрайты, CSS-материалы, canvas/WebGL, CSS-3D), новый рендер в Blender — только если без него нельзя.
- Blender 5.0.1 (`bpy`), Cycles CPU + OIDN: рецепты и скрипты — `tools/showroom-assets/` (`academy_hall.py` — `pack_mat()`, `auditorium/academy_auditorium.py` — `pbr()`, `grade_hall.py`, `regrade_site.py`), пак CC0-текстур `tools/showroom-assets/textures` (+ `manifest.json`). Любой новый рендер обязательно проходит подгонку цвета под сайт (`regrade_site.py --stats` до/после).

## 2. Технические правила

- Без новых библиотек и внешних сетевых запросов (CSP сайта строгий). Допустимы CSS-3D, Web Animations, canvas, WebGL (есть `js/jar-gl.js` как образец и страховка «нет WebGL»).
- 60 fps при прокрутке и анимации: анимируем только `transform`/`opacity`, слои `will-change` — только на время движения, тяжёлые эффекты — лениво (IntersectionObserver), фон-картинки — WebP, hero ≤ 450 КБ на ПК (до 4K — только если нужен резкий крупный план), `srcset`/`sizes`, `loading="lazy"` ниже первого экрана, `decoding="async"`, фиксированные размеры (без сдвига вёрстки).
- Адаптив: 1440 / 1024 / 768 / 390 px, без горизонтальной прокрутки, цели касания ≥ 44 px, контраст текста ≥ 4,5:1, видимый фокус, клавиатура везде, `aria` на интерактивных сценах. Без JS страница читаема (`<noscript>`/статичная разметка).
- Переход между страницами без перезагрузки уже есть (`js/motion.js` подгружает css/js новой страницы): ваш js вешается на разметку через тот же механизм, что `js/sales-pages.js` / `js/pages.js` (инициализация при показе страницы, очистка при уходе: таймеры, rAF, слушатели `window`).
- Свои стили и скрипты страницы подключаются автоматически, если файлы лежат в `css/` и `js/` и перечислены в `data/redesign.json → pageAssets` (строки уже заведены для всех страниц — `redesign.json` не править): `product` → `pg-product`; `brand` → `pg-brand`; `event` → `pg-event`; `article` → `news-article`; `start` → `pg-start`; `search` → `pg-search`; `privacy`/`terms`/`consent` → `pg-legal` (общий файл); `notfound` → `pg-404`; `partners` → `pg-partners`; `contacts` → `pg-contacts`; `news` → `news-paper`; `company` → `company-atrium`; `custom` → `pg-custom` (css/js с таким именем). Ключ страницы — `P.key` из `tools/build.js`. Все селекторы своего css — под корневым классом страницы (изоляция), общие классы (`.btn`, `.tag`, `.card`, `.chip`, формы) не переопределять глобально.
- Данные — из `data/*.json` через `ctx` (`src/data.js`); разметку страниц собирают `src/pages/*.js`. Нужны новые поля — добавляйте отдельным файлом/полем, не меняя прежние. Общие файлы (`src/components.js`, `src/layout.js`, `tools/build.js`, `js/shared.js`, `js/core.js`, `css/base.css`, `css/components.css`) — **не править**, а если без этого никак — только добавлением новой функции/правила и пометить в отчёте (правки сливаются вручную).
- Сохраняются: все `data-track`, `data-act`, `data-type`, id/классы, на которые опираются `js/*.js` и `tools/check-*.js`, параметры адреса (`?brand=…&cat=…`), якоря, JSON-LD, хлебные крошки (их генерирует сборка, но внешний вид — ваш), Стелла (помощник: подсказки через существующие `asst-open` / `asst-chip`, без второго чата и без правок бэкенда).

## 3. Процесс и проверка

- Работаете в своей ветке/рабочем дереве. Коммитите **только исходники**: `src/`, `css/`, `js/` (кроме `js/data.js`), `data/`, `assets/`, `tools/`, `docs/`. **Не коммитить** собранные `*.html`, `js/data.js`, `build.json` (их пересоберёт и закоммитит координатор). Собирайте локально `node tools/build.js` и проверяйте через `python3 -m http.server <ваш порт> --directory <ваше рабочее дерево>` (порты: товар/бренд/событие 8811, Стелла/поиск/юр./404 8812, партнёры/контакты 8813, новости 8814, компания 8815).
- Проверка: Playwright (Chromium, `--use-gl=swiftshader`) — скриншоты на 1440 и 390, прогон сценариев (формы, фильтры, клики, клавиатура), ошибок консоли нет. Новая проверка — `tools/check-<страница>.js` (по образцу `tools/check-academy.js`; сервер на порту 0). Существующие `tools/check-*.js`, затрагивающие вашу страницу, должны проходить; если проверка пишет про старый визуальный класс, который вы осознанно убрали, — обновите проверку под новый, сохранив смысл (функция должна остаться проверяемой).
- Документ страницы: `docs/PAGE-<имя>.md` (замысел, материалы, ассеты и как их пересобрать, проверки). Файлы `docs/DESIGN-SYSTEM.md` и общие — не править (координатор добавит ссылку).
- Реальная картина проверки честно: проверено только в Chromium без GPU (Playwright) и в Blender; не проверено на реальном GPU, Safari, iPhone — так и писать.
- Blender: не больше 2 потоков (`--threads 2`; на машине 4 ядра и работают несколько агентов), один рендер ≤ ≈ 40 мин, длинные — резюмируемыми полосами; исходники сцены и скрипты — в `tools/showroom-assets/<страница>/`, готовые WebP — `assets/<страница>/`, размеры ≤ 500 КБ на кадр.
