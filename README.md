# Астрея — сайт дистрибьютора профессиональной косметики

Статический многостраничный сайт без бэкенда и без внешних зависимостей. Страницы генерируются из `data/*.json` скриптом на Node.js
(только стандартная библиотека), поэтому сайт открывается с любого хостинга, в том числе с GitHub Pages, и с диска.

## Структура

```
index.html catalog.html brands.html training.html news.html company.html contacts.html partners.html search.html privacy.html terms.html 404.html
brands/<бренд>.html      страницы брендов (9)
products/<товар>.html    страницы товаров (30)
training/<мероприятие>.html   страницы мероприятий (7)
news/<новость>.html      страницы новостей (9)
css/   fonts · consent (уведомление о cookie) · base · components · pages · responsive · motion · redesign (слой доработок) · backdrops (фоновые вставки) · gallery (витрина каталога)
js/    shared (общий код для Node и браузера) · data (генерируется) · core · motion · pages · hero-mark · redesign (слой доработок) · backdrops (фоновые вставки) · gallery (витрина каталога)
assets/ favicon, иконки, og-image; assets/brands/ — логотипы брендов; assets/products/ — фото товаров (ставятся в админке, раздел «Товары по брендам»; пока фото нет, на карточке рисуется иллюстрация упаковки); assets/photos/ — фото для слоя доработок; assets/jar/ — кадры вступления с баночкой (рендер Blender, см. tools/jar-render); assets/bg/ — фоновые текстуры страниц (см. tools/bg-render)
data/  ВСЕ данные и тексты сайта (см. data/README.md)
src/   шаблоны страниц (функции, возвращающие HTML)
tools/ build.js — сборка · check.js — проверка · bundle.js — автономная сборка · redesign.js — включить/выключить слой доработок
server/ сервер заявок и админка сайта (Node.js без зависимостей) — см. server/README.md
docs/   LAUNCH.md — запуск в РФ: что нужно, что внедрено, что делает владелец, развёртывание
privacy.html consent.html terms.html   политика, отдельное согласие и соглашение (собираются из реквизитов, src/legal.js)
assets/fonts/ css/fonts.css   свои шрифты (страницы не обращаются к серверам Google)
sitemap.xml robots.txt .well-known/security.txt
```

HTML-файлы в корне и в `brands/ products/ training/ news/` — **результат сборки**: не правьте их руками, меняйте `data/` или `src/` и запускайте сборку.
`404.html` — страница «Такой страницы нет»: GitHub Pages сам отдаёт её на любой неверный адрес (на любой глубине), поэтому ссылки в ней идут от корня сайта (`/astreya/…`), а не «../»; из папки напрямую (file://) она не откроется — это нормально. Не попадает в sitemap (`noindex`). Аудит (`npm run audit`) открывает её по http.

## Сборка и проверка

```bash
node tools/build.js      # собрать сайт (страницы, js/data.js, sitemap.xml, robots.txt)
node tools/check.js      # проверить: битые ссылки и якоря, один <h1>, уникальные title/description, canonical, порядок заголовков
```

Требуется Node.js 16+. `npm run build` / `npm run check` делают то же самое.
В ссылки на CSS/JS при сборке добавляется версия (`?v=…`, хэш файлов и данных), поэтому после публикации браузер не показывает устаревшие стили; страницы при переходах запрашиваются с перепроверкой.
Автономный файл (все страницы в одном HTML, для предпросмотра или публикации там, где нет обычных файлов): `node tools/build.js --bundle=astreya.html`.

Поля, которых нет в данных (объём, артикул, показания, способ применения, документы, программа мероприятия, реквизиты), на страницах показываются как
«Уточняется — запросите у менеджера»: ничего не выдумывается. Как только вы заполните поле в JSON, соответствующий блок появится сам.
Всё демонстрационное помечено (`demo: true` и текст в подвале `demoNotice` в `site.json` — удалите его, когда данные станут реальными;
вместе с ним включится разметка Product/Event/NewsArticle для поисковиков).

## Переходы между страницами и обновление

Поведение как в прежней (одностраничной) версии сайта:

* **Обновление / первая загрузка любой страницы** — заставка с собирающимся логотипом (~2,2 с, по клику пропускается), затем полосы шторки поднимаются.
* **Переход по ссылке внутри сайта** — без перезагрузки: полосы шторки закрываются (820 мс) с титром раздела, содержимое `<main>` подменяется настоящей страницей
  (тот же файл, что видят поисковики), полосы поднимаются (700 мс), блоки появляются через 470 мс. Работает кнопка «Назад», адрес и заголовок вкладки меняются.
  Если подмена невозможна (файл открыт с диска, нет сети), выполняется обычный переход по ссылке под той же шторкой.
* **Поиск** (форма в шапке/в окне поиска/на странице результатов, подсказки, «Все результаты») открывает результаты **тихо** — без шторки и заставки: страница подменяется сразу и мягко проявляется
  (`go(url, push, quiet)` в `js/motion.js`; при открытии с диска — обычная загрузка, но ранний скрипт в `<head>` ставит `nav-quiet`, и заставка не показывается).
* При подмене страницы подключаются недостающие стили и скрипты (`syncAssets`): у главной есть `css/jar.css`/`js/jar.js`, у других страниц их нет — без этого возврат на главную по логотипу
  из каталога давал секцию вступления без оформления.
* Тайминги — в `js/motion.js` (`go`) и `css/motion.css` (блок `curtain`).
* **Лого и ссылки на главную** ведут к основной странице — герою, а не в начало вступления с баночкой: после перехода (и на самой главной по клику на лого) страница прокручивается к герою (`M.heroTop`/`M.scrollHome` в `js/motion.js`).
  Вступление остаётся выше героя: до него можно долистать вверх, кадры при этом перематываются назад. Заход на главную по адресу или в новой вкладке открывается с вступления, а **обновление страницы (F5, «перезагрузить») на главной открывает героя** — вступление показывается при заходе на сайт, а не при каждом обновлении (определяется по Navigation Timing, `js/motion.js`). Проверка: `npm run check:logo`.

## Плавность прокрутки

* Бесконечные декоративные анимации (кольца и орбиты героя, свечение, кнопка и маскот Стеллы) во время прокрутки стоят на паузе (`html.is-scrolling`, `css/motion.css`); анимации кнопки Стеллы конечные, а не бесконечные.
* Чтение вёрстки в обработчиках прокрутки и движения мыши запрещено правилом проекта: оно заставляет браузер пересчитать стили посреди прокрутки (так, слежение кнопки Стеллы за курсором ничего не читает, пока курсор далеко от кнопки; в обработчике прокрутки для подписи кнопки положение не читается вообще). Проверять просто: трассировка `UpdateLayoutTree` с «принудительными» пересчётами во время прокрутки должна показывать только `js/motion.js`.
* **«Лёгкий режим» по факту** (`js/motion.js`, `css/motion.css`): пока идёт прокрутка, считаются интервалы кадров; если в последних 30 кадрах не меньше 5 дольше 34 мс (≈ ниже 30 к/с), включается `html.lite` — блоки, заголовки и подписи появляются сразу, без переходов (`transition` у `.reveal`, `.split`, `.eyebrow`). Первые 6 секунд после загрузки и участки со сценой с баночкой не считаются; включившись, режим остаётся до перезагрузки страницы. На быстром компьютере он не включается, и анимация проявления остаётся прежней. В замерах (каталог, процессор замедлен ×4): кадров дольше 33 мс было 56 %, стало 24 %.
* Вступление с баночкой — своя система качества (три уровня и регулятор нагрузки, `js/jar.js`, подробности в `tools/jar-bench/README.md`).
* **Конструктивные причины микрофризов (найдены трассировкой, держит `tools/check-scroll.js`).** Измерялось в Chromium: занятость главного потока по видам работы, число и причины композиционных слоёв (`LayerTree`), причины инвалидации стилей, медианы по 3–5 прогонам (одиночные запуски шумят на ±30 %).
  — **Размытие фона (`backdrop-filter`) нельзя ставить на повторяющиеся элементы.** Три кнопки на каждой карточке (`.rl-add`, `.cmp-add`, `.qv-btn`) давали на каталоге 183 слоя, из них 90 — слои с размытием: браузер заново размывал то, что под ними, в каждом кадре прокрутки. Размытие убрано, фон кнопок плотнее (.94): слоёв 79, главный поток на ≈26 % свободнее, пересборка слоёв (`PaintArtifactCompositor::Update`) −48 %.
  — **Блокирующие слушатели прокрутки (`passive:false` на `wheel`/`touchmove`) допустимы только на время экскурсии Стеллы.** Они стояли на странице всегда, и браузер не мог прокручивать, не дожидаясь главного потока (на телефоне — на каждое касание). Теперь `js/guide.js` подключает их при включении блокировки и снимает при выключении. Единственный постоянный блокирующий слушатель — инерция колеса на компьютере (`js/motion.js`, нужна, потому что у части браузеров нет собственной плавной прокрутки колеса).
  — **Полоса чтения** писала `transform` в каждом кадре, и браузер каждый раз заново собирал слои (до 40 % работы главного потока на кадр). Теперь запись не чаще раза в 250 мс, а между записями — CSS-переход (300 мс) на компоновщике; на телефоне −30 % нагрузки на 1000 px прокрутки.
  — **Читать геометрию в кадрах прокрутки нельзя, пока блок вне экрана.** Подсветка «Почему Астрея» (`js/redesign.js`) читала `getBoundingClientRect` в каждом кадре на любой странице; теперь работает только пока список виден (`IntersectionObserver`).
  — **«Лёгкий режим»** включается дешевле в 4–6 раз: селектор перечисляет только элементы с переходами появления, а не «любой потомок блока» (`.reveal *` пересчитывал стили у всех потомков разом — разовая заминка именно тогда, когда устройство и так не успевает).
  — Не подтвердились (проверено, не менялось): реакция на курсор при прокрутке (≈0 % нагрузки), `will-change` у сцены с баночкой после её конца, распределение старта анимаций появления таймерами (всплесков стало больше), сокращение длительности появления (стоимость привязана к появлению слоя, а не к числу кадров), `decode()` кадров баночки (см. `tools/jar-bench/README.md`).
  — Что остаётся самым дорогим: появление блоков (создание и снятие слоёв: ≈40 % работы главного потока при прокрутке касанием на телефоне, из них ≈19 % — внутренний «зум» картинок карточек) и вступление с баночкой (декодирование кадров при холодном кэше). Оба — осознанные решения по внешнему виду; при слабом устройстве их отключает «лёгкий режим» (появление) и регулятор нагрузки (баночка).

## Формы

Формы (партнёр, запись на мероприятие, запрос по товару, вопрос, обратный звонок, подписка на новости, «Старт со Стеллой» при включённом `extras.sales`) **отправляют заявки в админку** (сервер из `server/`): `data/site.json → formEndpoint` по умолчанию `/api/lead`.

* **Сайт открыт через сервер** (`npm run admin` → <http://localhost:8080/>, либо сайт и сервер на одном хостинге): заявка сразу появляется в админке, в разделе «Заявки».
* **Сайт на GitHub Pages (статический хостинг):** `/api/lead` там не существует, форма честно покажет «Не удалось отправить заявку» с телефоном и письмом как запасным путём. Чтобы заявки с Pages попадали в админку,
  разместите сервер на хостинге с https и пропишите его полный адрес (`https://<сервер>/api/lead`) в `formEndpoint` — кнопкой в админке («Настройки и заявки → Подключение форм сайта») или вручную.
* **Режим письма (mailto)** остаётся для пустого `formEndpoint`: готовится письмо на `contacts.email`, интерфейс пишет «Заявка подготовлена». В автономном файле-предпросмотре (`build.js --bundle`, артефакт) сервера нет, поэтому там всегда этот режим.

Формат запроса: `POST` с JSON `{type, context, name, phone, email, city, org, spec, msg, page, sent_at, consent, fill_ms, src}` (`src` — необязательная метка источника заявки до 200 знаков: страница, элемент, варианты проверок; в админке — «Источник»); сервер проверяет поля, защищает от спама, сохраняет заявку и присылает уведомление.
Ответ 2xx — успех; 422 — поля подсвечиваются, данные остаются; 429 — «слишком много заявок»; обрыв сети/другая ошибка — сообщение с сохранёнными данными и запасными контактами (телефон, письмо).
В форме есть скрытое поле-ловушка для ботов; `fill_ms` — сколько форму заполняли (бот отправляет мгновенно). Любой другой бэкенд с тем же JSON тоже подойдёт.

## Админка и заявки

`server/` — сервер (Node.js 18+, без зависимостей): приём заявок, админка на `/admin/` (заявки, правка содержимого, картинки, пересборка, публикация, пользователи, уведомления), раздача сайта.
GitHub Pages не выполняет серверный код, поэтому сервер запускается отдельно (VPS / Render / Docker); сайт при этом может оставаться на Pages. Установка, переменные окружения, безопасность,
подключение форм и тесты — в [`server/README.md`](server/README.md). Быстрый старт: `npm run admin` → <http://localhost:8080/admin/>.

## Аналитика

**Яндекс Метрика** подключается из админки (Интеграции → номер счётчика, `data/integrations.json`): `js/consent.js` загружает счётчик только по правилам выбранного режима согласия (по умолчанию — после «Принять»), цели создаются из списка `metrika.goals`, переходы без перезагрузки считаются просмотрами. Все события уходят в `window.dataLayer` и в DOM-событие `astreya:track`, а при включённой Метрике — в `ym(…, 'reachGoal')`.
Запуск в РФ (152-ФЗ, согласие, документы, безопасность, развёртывание) описан в [`docs/LAUNCH.md`](docs/LAUNCH.md). События: `partner_cta` (кнопки «Стать партнёром», с `place`), `form_open`, `form_submit`, `form_error`,
`phone_click`, `email_click`, `messenger_click`, `catalog_click`, `catalog_view`, `catalog_filter`, `product_card_click`, `product_view`, `product_request`,
`event_register`, `brand_card_click`, `search`, `search_result_click`, `picker_select`. Разметка: атрибуты `data-track="…" data-place="…"`.

## SEO

У каждой страницы свои `title`, `description`, `canonical`, Open Graph/Twitter, favicon; JSON-LD: Organization + WebSite (главная), BreadcrumbList, FAQPage (обучение).
`robots.txt` и `sitemap.xml` собираются автоматически (страница поиска закрыта от индексации). Адрес сайта для canonical/sitemap — `site.json` → `url`.

## Помощник «Стелла» (мини-консультант — чат справа внизу)

Помощника зовут **Стелла** (от лат. *stella* — «звезда», как и «Астрея»; в коде имя встречается только в текстах чата, `js/assistant*.js`, `server/lib/assistant.js` — менять в одном-двух местах) — это жемчужинка со звёздочкой, талисман «Астрея»: жемчуг — про красоту и уход, звезда — про имя компании. Включается флагом `extras.assistant`. Файлы: `js/assistant.js` (интерфейс), `js/assistant-brain.js` («мозг»), `js/kb.js` (база знаний — собирает `tools/build.js` из `data/*.json`, чат подгружает её при первом открытии), `server/lib/assistant.js` (ИИ-режим), стили — в `css/extras.css`.

**Как он «думает».** Встроенный «мозг» работает всегда (в том числе на GitHub Pages и в автономном файле) и **ничего никуда не отправляет**:
* понимает вопрос с опечатками («пигментацыя», «семинарры», «дермотайм»), падежами и разговорными формулировками;
* **помнит ход разговора**: «а у Dermatime?», «ещё», «подробнее про второй», «почему именно эти?», «с чем сочетать?», «сравни их», «для кабинета / для дома», «да» на собственный вопрос;
* запоминает роль и город («я косметолог из Ростова»): семинары сразу по городу, форма партнёра заполняется по роли;
* **считает**: скидку по названной сумме («а при 200 тысячах?» → 10%, экономия, сколько не хватает до следующего порога), дни до мероприятия, расписание по месяцу / неделе / городу / формату;
* **сравнивает** товары словами (бренды, общие и различающиеся задачи) и объясняет, почему порекомендовал именно это — со ссылкой на описание задачи с сайта;
* ищет по материалам сайта (о компании, обучение, партнёрам, новости, бренды) и отвечает найденным предложением, а на непонятное говорит «возможно, вы имели в виду…» и предлагает передать вопрос менеджеру. Цены, наличие, сроки, сертификаты и медицинские рекомендации — **честно «этого на сайте нет»**.

**Живые реплики на «нестандартные» вопросы (без ИИ).** Если вопрос не про каталог и не про расписание, отвечает библиотека реплик — `data/stella/*.json` (≈ 180 тем, ≈ 450 вариантов ответа, подробно — `data/stella/README.md`). План такой: **1) о самой Стелле** — имя, возраст, «ты настоящая?», кто создал, как работает, чувства, любимое, недостатки, комплименты и грубости; **2) светская беседа и служебные реплики** — «как дела», «подожди», «ок», «повтори», «объясни проще», «давай сначала», настроение, праздники, поздравления; **3) игры и расчёты** — загадки с проверкой ответа, факты и шутки (по кругу, без повторов), монетка, кубик, случайное число, «да или нет», дни до Нового года / 8 Марта / выходных, «какое число будет через 10 дней», запоминание имени на время разговора; **4) не по теме сайта** — погода, политика, финансы, кино, рецепты, код, тексты, домашние задания, гороскопы: вежливо, без выдумок и с возвращением к делу; **5) чего на сайте нет** — возврат, оплата, пробники, вакансии, соцсети, маркетплейсы, «веган / органика», дети: честно «этого на сайте нет» и контакты менеджера из данных сайта; **6) тяжёлое и опасное** — кризис и экстренные симптомы (112, без «продаж»), реакция кожи (к врачу), грубость, попытки «взломать» инструкции, незаконное, номера карт и ссылки в чате; **7) мини-справочник** из ≈ 30 терминов (SPF, ретинол, пилинг, комедоны, фототип…) — общая справка с оговоркой «подбор — со специалистом»; **8) «лестница» запасных ответов** — непонятное не получает один и тот же отказ: ответ зависит от вида фразы (вопрос, просьба-задание, одно слово, случайные буквы, английский, украинский…), а после трёх промахов подряд Стелла прямо предлагает позвать менеджера. Помогают и мелочи: фразы с опечатками и растянутыми буквами («приветтт»), набор «не в той раскладке» («ghbdtn» читается как «привет»), смайлики, приветствие вместе с вопросом. Реплики повторного вопроса меняются, а примерно в каждом втором ответе вторым сообщением идёт «мостик» к делу. Проверка — `npm run check:stella` (≈ 800 формулировок, все названия из каталога, расписания, FAQ и новостей, диалоги и расчёты); при включённом ИИ эти ответы остаются запасными, а безопасные и служебные (`local`) отвечаются сразу.

**ИИ-режим (необязательный)** — для свободных вопросов. Сервер из `server/` даёт модели **инструменты** (поиск товаров, карточка товара и бренда, расписание, расчёт скидки, контакты, поиск по материалам сайта), модель сама решает, что проверить, вызывает их, а сервер выполняет по данным сайта; ответ приходит потоком, в чате видны шаги («Ищу в каталоге…»). **Работает с любым сервисом ИИ:** Claude (Anthropic) или любой OpenAI-совместимый — OpenAI, OpenRouter, Google Gemini, Groq, DeepSeek, Mistral, xAI, Together, а также модели на своём компьютере/сервере (Ollama, LM Studio, vLLM — для них ключ не нужен). Сервис выбирается в админке одним списком (адрес подставляется сам; можно вписать и свой) либо переменными `ASSISTANT_PROVIDER` (`anthropic` | `openai`), `ASSISTANT_BASE_URL`, `ASSISTANT_API_KEY` (подойдут и привычные `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`) и `ASSISTANT_MODEL` (идентификатор модели — **обязательно, в репозитории намеренно не прописан**; берите актуальный из документации выбранного сервиса). Если модель не умеет вызывать функции, сервер сам переключается на режим без инструментов (каталог передаётся прямо в инструкции; принудительно — `ASSISTANT_TOOLS=0` или галочка в админке). Необязательно:  `ASSISTANT_MAX_TOKENS` (1200), `ASSISTANT_RATE` (сообщений с адреса за 10 минут, 20), `ASSISTANT_DAILY` (всего за сутки, 400). Пакет `@anthropic-ai/sdk` нужен только для Claude (необязательная зависимость: `npm install` в корне; в Docker ставится сам); OpenAI-совместимые сервисы работают через встроенный `fetch` без зависимостей (`server/lib/llm-openai.js`). **Стелла отвечает не только по сайту:** с включённым ИИ она поддерживает разговор на любую тему (общие вопросы, объяснения, тексты, перевод, код, расчёты), а факты о компании, каталоге, расписании, скидках и контактах берёт из инструментов — не из памяти модели. В инструкции модели прямо сказано: выхода в интернет у неё нет (свежих новостей, погоды и курсов она не знает и не выдумывает), медицина/право/финансы — только общая справка с предупреждением, вредные просьбы отклоняются, просьбы «забыть правила» игнорируются. Точные и служебные вещи (контакты, звонок, цены/наличие, скидки, расписание, формы, **арифметика и дата/время**, продолжение диалога) по-прежнему отвечает «мозг» — мгновенно, бесплатно и без «выдумок»; светская беседа, «о компании», партнёрство, новости, каталог, медицинские и любые свободные вопросы при включённом ИИ уходят к модели. Нет ключа, модели, пакета или лимит исчерпан — чат молча работает во встроенном режиме. Адрес берётся из `formEndpoint` (`…/api/lead` → `…/api/assistant`), проверить: `GET /api/assistant/status`.

**Подключить ИИ (три шага):** 1) на сервере выполните `npm install` в корне проекта (в Docker ставится сам); 2) в админке откройте «Настройки и заявки → ИИ-помощник сайта «Стелла»», выберите **сервис** (Claude, OpenAI, OpenRouter, Gemini, Groq, DeepSeek, Mistral, xAI, Together, Ollama или «другой»), вставьте **ключ API** и **модель** (идентификатор из документации выбранного сервиса) и нажмите **«Сохранить и проверить»** — кнопка отправляет пробный запрос и понятно объясняет сбой (ключ, модель, лимит, сеть); 3) готово, перезапуск не нужен. Вместо админки можно задать `ASSISTANT_PROVIDER`, `ASSISTANT_BASE_URL`, `ASSISTANT_API_KEY` и `ASSISTANT_MODEL` в окружении сервера или в файле `server/.env` (шаблон — `server/.env.example`; они главнее настроек админки). Проверка из консоли: `node server/cli.js assistant-check`. Нужен сервер из `server/`: на статичном хостинге (GitHub Pages без сервера, автономный файл-предпросмотр) ИИ работать не может — там чат остаётся во встроенном режиме. Без ключа чат работает во встроенном режиме и честно говорит, что на вопросы вне сайта пока не ответит. В репозитории проверить настоящую модель нельзя (ключа нет), поэтому серверный путь проверен на **настоящем пакете `@anthropic-ai/sdk` против локальной имитации API** (`server/test/assistant-sdk.test.js`: формат запроса, потоковые события, вызов инструментов, ошибки 401/404/429, остановка запроса) и так же для OpenAI-совместимого клиента (`server/test/assistant-openai.test.js`: перевод запроса и потока, вызовы инструментов, `max_tokens` ↔ `max_completion_tokens`, ответ без потока, сервис без инструментов, ошибки, остановка). Реальные вызовы сервисов без ключей проверить нельзя — это единственное, что остаётся проверить при первом подключении (кнопка «Сохранить и проверить») и в браузере на поддельном клиенте (`tools/check-assistant-ai.js`).

**Интерфейс (по лучшим практикам чатов 2026 года).** Кнопка с жемчужинкой появляется как небольшая «сцена» (≈ 3,5 секунды, без перелётов и рывков): круг медленно проявляется со свечением → искры слетаются к жемчужинке и вспыхивают → Стелла проявляется с закрытыми глазами и «просыпается» → машет; потом «парит», моргает, глаза Стеллы следят за курсором, а сама кнопка слегка тянется к нему (только мышь, и только когда курсор рядом: вдали кнопка вёрстку не читает и стили не пишет). Подпись «Спросить Стеллу» **при загрузке сама не раскрывается** и блика на кнопке нет (в замерах кнопка с эффектами на старте заметно добавляла долгих кадров): она раскрывается **один раз после первой прокрутки** — через 0,35 с после того, как человек остановился: жемчужинка «выкатывается» из круглешка — катится влево, делая один оборот, и тянет за собой плашку (ширина и поворот идут синхронно), подпись остаётся открытой 2 секунды и снова сворачивается; кроме того, подпись раскрывается при наведении/фокусе. На телефоне кнопка круглая, без подписи (плавность проверяется покадрово: `npm run check:motion`). Раз в сессию Стелла подсказывает по теме страницы (без фальшивых «непрочитанных»). **Панель раскрывается неторопливо, элементы шапки появляются по очереди; вопрос «вылетает» из поля ввода в ленту. Ответы приходят «как в мессенджере»:** вопрос помечается ✓, затем ✓✓ («прочитано»), Стелла «думает» (индикатор и статусы шагов — «Читаю вопрос…», «Ищу в каталоге…», «Подбираю слова…»; 0,65–2,4 с в зависимости от сложности, с ИИ — не меньше секунды до первых слов), сообщение «отправляется» (всплывает) и печатается со скоростью живой речи (на знаках препинания короткие паузы); первое приветствие тоже печатается. Настроение Стеллы меняется: ждёт, думает, говорит, радуется. «Стоп» работает на любом шаге (во время раздумья, до обращения к серверу и во время печати). Над Стеллой, пока она думает, всплывают «мысли»-искорки, а её взгляд скользит из стороны в сторону. В ответах ИИ оформляются **жирный**, списки и блоки кода. Анимации работают **всегда** — и при системной настройке «уменьшить движение»: переключателей и «спокойного режима» нет (так решено для сайта). `window.ASTREYA_MOTION_SPEED = 6` ускоряет все паузы и печать — только для автоматических проверок. Панель раскрывается из кнопки, на телефоне — шторкой во весь экран; быстрые ответы идут **внутри ленты** и ничего не перекрывают; ответ «печатается» (на телефоне и при `prefers-reduced-motion` — сразу целиком), кнопка «Стоп» оставляет напечатанное; под ответом 👍/👎 (👎 → предложение передать менеджеру); в шапке всегда есть «Связаться с менеджером»; голосовой ввод (если браузер умеет); карточки товаров с «+» в список запроса и сравнением; скринридер получает готовый ответ целиком, а не побуквенно. Честная пометка «я программа, а не сотрудник» и, в ИИ-режиме, предупреждение о том, что вопросы обрабатываются на сервере и в сервисе ИИ.

**Инструменты для ИИ-агентов (`extras.agentReady`, экспериментально).** `llms.txt` в корне сайта (формат [llmstxt.org](https://llmstxt.org): о компании, бренды, расписание, ссылки — из данных сайта), `manifest.webmanifest` (установка на главный экран телефона) и **WebMCP**: если браузер поддерживает `navigator.modelContext` / `document.modelContext`, страница отдаёт ИИ-агентам четыре инструмента только для чтения (`search_products`, `list_events`, `discount_for_amount`, `get_contacts`). Спецификация WebMCP ещё меняется и поддерживается не везде — код перед использованием проверяет возможность браузера и ничего не ломает без неё.

Диалог хранится в `sessionStorage` вкладки (не на сервере); сервер диалоги не сохраняет и не пишет в журнал. **Выключить:** `"assistant": false` и `npm run build` (`js/kb.js` удалится); `"agentReady": false` убирает `llms.txt`, манифест и WebMCP. **Проверки:** `npm run check:motion` (покадровая запись появления кнопки Стеллы: без перелёта и рывков), `npm run check:stella` (библиотека живых реплик), `npm run check:assistant` (разговоры с «мозгом» на реальных данных + весь путь ИИ-режима в браузере на поддельной модели, сеть не нужна), `npm run check:extras`, `node --test server/test/assistant.test.js`.

## Стелла-навигатор (extras.navigator)

Стелла — не только чат: она **ведёт по сайту** (что-то вроде «Джарвиса»). Всё настраивается в `data/stella/guide.json` (страницы, что можно подсветить, экскурсии, тексты подсказок, формат сравнения; сборка кладёт его в `js/data.js` → `ASTREYA_DATA.guide`). Откат — флаг `"navigator": false` (см. «Доработки и откат»).

* **Команды словами.** «Открой каталог», «покажи бренды», «где фильтры?», «где калькулятор скидок?», «отфильтруй по пигментации», «покажи только Dermatime», «проведи по сайту», «как сделать заказ? проведи по шагам», «наверх». Стелла отвечает и выполняет сама: переходит на страницу, **подсвечивает** нужный элемент (затемнение вокруг, подсказка рядом, следит за прокруткой), выставляет фильтры каталога, ведёт **экскурсию по шагам** (она переживает переходы между страницами; на телефоне — нижняя «шторка»). Команды разбирает встроенный «мозг» (мгновенно, бесплатно, с включённым ИИ тоже), без экрана — они остаются кнопками в чате. Исполняет их `js/guide.js` (`A.guide.run / show / tour / go / filter`).
* **Экскурсия «Покажи сайт» (интерактивная, со «своим курсором»).** Запускается **только по желанию посетителя**: кнопка-компас в шапке панели Стеллы, быстрый ответ «Покажи сайт» или фраза «проведи по сайту». Сама при заходе на сайт не появляется. Девять этапов с индикатором «2 из 9» и кнопками «Назад», «Далее», «Пропустить» проводят по **всем разделам**, в каждом — **несколько мест и действий** (32 шага): **1) Главная** (шапка с меню и поиском; кнопки первого экрана — Стелла сама нажимает «Открыть каталог»), **2) Каталог** (курсор нажимает на строку поиска и **неспешно печатает** слово по буквам — поле подсвечено синим; открывает список «Назначение» и **выбирает «Пигментацию»**; нажимает плитку категории; ⇄ сравнение — «Показать на примере» только по вашему нажатию; открывает карточку товара: факты, «В список запроса», «Запросить информацию»), **3) Бренды** (выбор по задаче, карточка бренда), **4) Обучение** (календарь, город и формат, пример встречи, преподаватели, материалы), **5) Новости** (вкладка, пример записи, подписка), **6) Компания** (о нас, ваш регион, почему можно доверять), **7) Партнёрам** (преимущества, **ползунок калькулятора скидки** тянется до порога 10 % — это ориентир; ступени; **заявка — Стелла сама заполняет её придуманными данными**: курсор переходит от поля к полю, печатает вымышленные имя, телефон, почту на example.com, город, организацию, выбирает специализацию и пишет короткий комментарий; согласие и «Отправить» оставляет вам, ничего не уходит на сервер, при «Пропустить» всё стирается), **8) «Старт со Стеллой»**, **9) Контакты** (так же заполняет форму вопроса) и финал с кнопками «Вернуться на главную», «Старт со Стеллой» и «Спросить Стеллу». К следующему разделу Стелла идёт **сама**: подсвечивает пункт меню, плывёт к нему курсором и нажимает. Порядок на каждом шаге: страница доезжает (слов Стеллы и рамки при этом не видно) → рамка → комментарий Стеллы → пауза на чтение → только потом действие; комментарий всегда стоит на одном месте (на компьютере — внизу по центру, на телефоне — нижняя «шторка»), не закрывает показ и подстраивать его не нужно. На телефоне курсора на экране нет. Рамка подсветки всегда обходит блок целиком, прокрутка между частями страницы плавная; первый шаг показывает главную на первом кадре героя. **Страница на время показа закреплена** — колесо, палец и клавиши её не двигают, подсвеченный абзац и Стелла стоят на месте. Всё, что она изменила на странице (запрос, фильтры, ползунок, отметки сравнения), возвращается назад при выходе. Тексты шагов — **своими словами** (не пересказ заголовков страниц), коротко и по формуле «что это → что даёт → как пользоваться», без одинаковых зачинов и без «мостиков» вроде «Идём дальше»; корзину и заявки экскурсия не трогает, форм не отправляет. Правка шагов — `data/stella/guide.json → tours[site]`, язык сценариев шагов (`acts`) — в `data/stella/README.md`.
* **Сравнение — через Стеллу, таблицы нет.** ⇄ на карточке добавляет товар (до трёх); внизу плашка со списком выбранного и кнопкой **«Попросить Стеллу рассказать»**. Стелла открывает чат и **излагает факты по данным сайта**: что общего, чем отличаются, кому что ближе, чего на сайте нет (цен, состава, наличия) — плюс карточки товаров и кнопка «Запросить информацию». Описания со страниц **не цитируются**: Стелла говорит своими словами и оставляет только факты (бренд, раздел, задачи, чего на сайте нет). Это работает и без ИИ, и с ИИ (для сравнения ИИ не нужен и денег не тратит); «Расскажи подробнее» после сравнения уходит к ИИ уже с контекстом. Формат ответа (`compare.template`: `sections` · `verdict` · `cards` · `lines` · `brief`) выбрала арена. «Спросить Стеллу» есть и в быстром просмотре товара.
* **Где Стелла «заговаривает» сама.** Блок «Не знаете, что выбрать?» с готовыми вопросами-кнопками есть на каждой странице (главная, каталог, бренды, страница бренда, товар, обучение, мероприятие, партнёрам, контакты, о компании, новости, поиск, 404); тексты — от первого лица, у многих по два варианта (при каждом заходе показывается один). **Приветствие** — **только на главной** и прямо **на плашке Стеллы** «Не знаете, с чего начать?» (не у правого нижнего угла): когда посетитель долистал до плашки и она заметна на экране (≥ 60 %), один раз за сессию рядом с маскотом появляется небольшое окно «Добро пожаловать на сайт! Чем могу помочь? …» с хвостиком, указывающим на жемчужинку (на широком экране — слева от плашки, на узком и на телефоне — над ней), маскот при этом «машет». Оно не появляется, пока идёт вступление с баночкой, и не перебивает: ни при открытом чате, ни во время экскурсии, ни в меню; закрывается крестиком и сама исчезает через 20 секунд. Тексты — `data/stella/guide.json → entry.pages.home.hello` (`title`, `text`, `showSec`; по два варианта). Старое окно у кнопки Стеллы справа внизу отключено (`nudge.pages: []`; вернуть — `"pages": ["home"]`). На остальных страницах всплывающих окон нет вообще.
* **Стелла знает контекст:** на какой вы странице, какой товар/бренд/мероприятие открыт («этот товар», «у этого бренда»), что отмечено для сравнения — это уходит и в запрос к ИИ служебной строкой в квадратных скобках.
* **Живой диалог — во всей системе Стеллы (`data/stella/voice.json`).** Ответы без ИИ складываются из **её слов**, а не из абзацев со страниц: факты (названия, задачи, числа, даты, контакты) берутся из данных, а оборот речи — из пулов реплик (приветствие по странице и времени суток, о товаре, бренде, задаче, расписании, скидках, контактах, партнёрстве, компании, новостях, сравнении). Варианты идут по кругу — повторный вопрос получает другую фразу («И снова здравствуйте»); о себе Стелла говорит в женском роде; в конце — **встречный вопрос**, и «да» его подхватывает (оформить запрос по товару, записаться на семинар, открыть форму партнёра, заказать звонок, показать сайт). Помнит роль, город, имя и задачи посетителя. Проверки: `node tools/check-assistant.js` (раздел 11: ни одного дословного куска страниц — пять слов подряд — в ответах; разные реплики при повторе; встречные вопросы и «да»), `node tools/check-stella.js` (раздел «Голос Стеллы»: подстановки, два варианта и больше, женский род, без давления).
* **Рамки (что бы ни написала модель).** Код `js/stella-policy.js` (общий для браузера и сервера) гарантирует: **1)** ссылки только на этот сайт — внешние адреса и markdown-ссылки вырезаются (на сервере в потоке и ещё раз в браузере); **2)** названия товаров и брендов из каталога в тексте становятся ссылками на наши страницы, а упомянутые товары — карточками; **3)** под объяснениями о коже, уходе, ингредиентах, процедурах, питании и здоровье — плашка **«Справочная информация · не медицинская рекомендация»** (по словарю тем или по метке `[[med]]`); **4)** маркеры действий от ИИ (`[[show:…]]`, `[[go:…]]`, `[[tour:…]]`, `[[filter:…]]`, `[[compare:…]]`) становятся кнопками, только если цель, страница, экскурсия, фильтр и товар есть в настройках и данных; сами по себе они ничего не выполняют.
* **Инструкция для ИИ** — `server/lib/stella-prompt.js`. Рамки: **«ответ → мост → шаг»**: Стелла отвечает на любой вопрос (вплоть до «хочу покушать»), затем одним-двумя предложениями ведёт тему к коже, уходу, косметологии и сайту и предлагает шаг (подобрать, показать, сравнить, записаться); не навязывает при горе, болезни, кризисе, просьбе не продавать. Каждое объяснение **обосновано** («по данным каталога…» / «по общеизвестным сведениям…»), без выдуманных источников, цифр и «нашла в интернете» (доступа в интернет у модели нет); без диагнозов, назначений и обещаний. Навигация (страницы, цели подсветки, экскурсии) подставляется в инструкцию из `guide.json`. Появился инструмент `compare_products` (факты сравнения). Без ИИ то же «бытовое» поведение даёт библиотека реплик: `data/stella/daily.json` («хочу покушать», «хочу кофе», «не выспалась», «много работы»… — ответ по-человечески и мягкий мостик к каталогу). Отдельные правила **«своими словами»** (не копировать тексты страниц, оставлять точными только факты) и **«живого диалога»** (разные зачины, помнить сказанное посетителем, женский род, встречный вопрос — но не в каждой реплике).
* **Арена** (`npm run arena:stella`; отчёт — `tools/arena-stella-report.md`): турнир вариантов по **измеримым** критериям — это не опрос посетителей и не A/B-тест (данных о людях пока нет, их покажет аналитика: события `guide_nudge`, `stella_compare`, `cmp_ask_stella`, `guide_spot`). Соревнуются: формат ответа-сравнения (по всем 435 парам и тысячам троек каталога), оформление подсказки / блока на странице / плашки сравнения (в Chromium на 7 размерах экрана и 5 страницах: влезает ли, наезды на другие кнопки, контраст, размер нажимаемого, строки, сдвиг вёрстки), тексты подсказок для каждой страницы (по 13 вариантов, в том числе заведомо плохие «давящие» — контрольные, они обязаны проиграть). Победители записываются в `guide.json` (`arena`); сейчас: формат сравнения — `sections` (общее → различия → кому что ближе → чего на сайте нет), подсказка — `bubble` (с кнопками-вопросами), блок на странице — `strip`, плашка сравнения — `stacked`. Веса критериев выбраны под приоритет заказчика — информативность и помощь важнее компактности; весь ход (включая то, что первый прогон выбрал другое и нашёл наезд подсказки на нижнюю плашку на экранах 1024–1440 px — это исправлено) записан в отчёте. Формулировку заказчика для главной и каталога арена не меняет.
* **Проверки:** `npm run check:navigator` (браузер: сравнение через Стеллу, команды, экскурсии с переходами, точки входа на всех типах страниц, подсказка, телефон, «рамки» ИИ с поддельным клиентом), `npm run check:assistant` включает его; `node tools/check-stella.js` (библиотека реплик), `npm run test:server` (в т. ч. инструкция Стеллы и фильтр внешних адресов).

## Продающий слой «Путь к закупке» (extras.sales)

Цель — чтобы посетителю было проще сделать следующий шаг (подобрать, записаться, запросить условия), а менеджер получал **готовый, осмысленный** запрос. Подробный плейбук (исследование 2026 года, что внедрено и что отклонено, как измерять вместо «обещания 90 %») — **`data/sales/README.md`**. Коротко:

* **«Старт со Стеллой»** (бывший «Стартовый подбор») — страница `start.html` (нет в меню, шапка не меняется): **диалог со Стеллой** прямо на странице — 3–5 вопросов (по умолчанию — выбор арены: задачи → цель → город), ответ кнопкой-вариантом или своими словами (в том числе несколько ответов одной фразой) → **план**: линейки, товары, ближайшие семинары, пороги скидок; кнопки «Получить подбор от менеджера» (заявка типа «plan» с уже подставленным планом), «Добавить товары в список запроса» (только по нажатию), «Скопировать ссылку на план», «Спросить Стеллу о плане». План хранится в браузере только на время захода (`sessionStorage astreya:plan`, как и черновик ответов): при каждом новом заходе на сайт (новая вкладка или после закрытия браузера) «Старт со Стеллой» начинается заново; прежние сохранения в `localStorage` при загрузке удаляются. План открывается по ссылке (`?t=acne,pigment&g=both&c=Москва`).
* **Панель следующего шага** — плашка в «доке» внизу экрана; текст по типу страницы (товар, бренд, мероприятие, обучение, каталог, партнёры, прочие). Телефон — по умолчанию, компьютер — только в эксперименте `barDesktop`. Появляется после ≈30 % прокрутки или 12 с, закрывается крестиком (до конца сессии), не мешает окнам, меню, чату Стеллы, списку запроса, подвалу и форме заявки.
* **Свой ход на каждой странице** (вместо одинаковых блоков «Что дальше / Доверие», которых больше нет): **главная** — без новых разделов (в блоке «Для кого» — адресные кнопки на подбор под роль); **каталог** — «Подборки по задачам» каруселью (одна подборка спереди, две на заднем плане; в список запроса одним нажатием); **бренды** — «билет» с датой ближайшего семинара на карточке; **бренд** — маршрут «Освоить → Выбрать → Заказать»; **товар** — «Освоить в работе» и «Что будет после запроса»; **обучение** — «Календарь встреч» (сетка месяца с отмеченными днями, фильтр по городу); **мероприятие** — «Как проходит запись» и «Позвать коллегу»; **партнёрам** — ориентир скидки («до 10 % не хватает …»); **новости/статьи** — завершающий призыв по теме; **компания** — «Ваш регион» (ячейки городов) и блок «Почему «Астрея» можно доверять»; **контакты** — «Сейчас на связи»; **поиск** — «Не нашли нужное?». Таблица «страница → ход → психология → как измеряем» — в `data/sales/README.md`. После отправленной заявки — «что дальше» (обучение, подбор, список запроса).
* **Кнопка «Старт со Стеллой»** заменила прежнюю «Подобрать средство по задаче» везде (блок «Не знаете, что выбрать?», пузырь-подсказка, быстрые ответы в чате, финал экскурсии): синяя, ведёт на страницу `start.html`, а не в чат. Подмена идёт при отрисовке (`A.planChip` в `js/assistant.js`); без продающего слоя всё работает по-старому.
* **Диалог подбора**: цель «Сразу подобрать ассортимент» **не уводит в каталог сама**: Стелла не задаёт вопрос про город, собирает план и показывает сводку, а в реплике намекает: «Спокойно изучите стартовый план… когда будете готовы — нажмите синюю кнопку». Переход — по синей кнопке «Открыть каталог» (в диалоге и в конце плана) с фильтром по задаче; про обучение — лишь совет. Финальные реплики разные под каждый план; в итоговом плане — блок «Коротко по делу» с краткими фактами (справочные и по данным сайта; тексты — `data/sales.json → planner.facts`, `planner.chat`).
* **Метка источника заявки** (`src`, до 200 знаков): `p=страница;via=элемент;x=варианты проверок;plan=…` — видна в админке, CSV и письме. События аналитики: `sales_*`, `plan_*`.
* **Стелла** остаётся помощником, а не центром: честные ответы про «с чего начать», «хочу купить» (корзины нет — заказ через менеджера), «надо подумать» (без давления), подлинность, «мой план» (пересказывает сохранённый подбор); в промпте ИИ — правила честных продаж (`server/lib/stella-prompt.js`).
* **Что не меняется:** вступление, герой с анимированным логотипом и орбитой брендов, бегущая строка, шапка, подвал, меню, фирменный дизайн; остальные разделы главной совпадают с версией до слоя побайтно (проверяет `check-sales`) — изменены только адресные кнопки в блоке «Для кого». Без слоя остаются 404 и юридические страницы (`data/sales.json → exclude`); панель следующего шага не показывается на главной, контактах, поиске и подборе (`barExclude`).
* **Оформление:** «картотека» — прямоугольные карточки с цветной шиной, крупные цифры, календарная сетка, ступени; по просьбе заказчика на главной и в маршруте бренда нет кругов и жемчужин.
* **Честность:** нет таймеров «акций», выдуманного дефицита, «сейчас смотрят», отзывов и стыдящих отказов; суммы и проценты — только из `data/site.json`; согласие на обработку данных не отмечено заранее. Это проверяется автоматически.
* **Файлы:** `data/sales.json` (тексты и настройки), `data/stella/sales.json` (реплики), `data/sales/README.md` (плейбук), `js/sales.js` (ядро: подбор, панель, источник заявок), `js/sales-pages.js` (ходы по страницам), `css/sales.css`, `css/sales-pages.css`, `src/pages/start.js`, `src/pages/sales-home.js` (главная). **Проверки:** `npm run check:sales` (браузер + настоящий сервер заявок, 120+ проверок), `npm run arena:sales` (арена вариантов оформления по измеримым признакам; `--apply` записывает победителей в `data/sales.json → variants`). **Выключить:** `"sales": false` в `data/redesign.json` → `node tools/build.js`; откат кода — ветки `pre-modules-rollback` (до ходов по страницам) и `pre-sales-rollback` (до всего слоя).
* **Проверка вариантов вручную:** `?x=barDesktop:pill,ctaCopy:info` (эксперименты), `?v=planFlow:four,barStyle:pill` (оформление) — действуют только на этой загрузке страницы.

## Витрина каталога (extras.gallery)

«Astreya Interactive Beauty Gallery»: точечное развитие страницы `catalog.html` — без нового дизайна, без смены адресов, данных и логики фильтров. Файлы: `css/gallery.css`, `js/gallery.js` (подключаются **только** странице каталога, сразу после `explore.js`), два вызова в `js/pages.js` (`apply()` сообщает витрине, что изменился фильтр). Новых библиотек нет: CSS, Web Animations API, `IntersectionObserver` уже в проекте. Вес — около 10 КБ в сжатом виде.

| Что | Как устроено |
|---|---|
| **Вход** | заголовок и вводная проявляются штатным `.reveal`; карточки — короткий каскад (задержка 0 → 0,05 → 0,1 → 0,15 с по ряду, проявление 0,7–0,85 с: opacity, translate, scale). При повторных фильтрах заставка не запускается: карточка проявляется один раз |
| **Наведение** | карточка приподнимается на 6 px, упаковка плавно растёт (×1,07), тень глубже, на фоне упаковки — мягкий свет за курсором, «Быстрый просмотр» проявляется (абсолютный элемент: вёрстка не прыгает). Состояние `.is-hov` ставится по координатам курсора в раскладке сетки, а не по `:hover`: приподнятая карточка уходит из-под курсора на нижней кромке, и обычный `:hover` «дребезжал» бы. С клавиатуры — `:has(:focus-visible)`. На телефоне наведения нет |
| **Расширенный вид** | существующее окно «Быстрый просмотр»: упаковка «перелетает» из карточки в окно (копия `.art` анимирует размер, ≈0,5 с) и возвращается при закрытии; крупная упаковка (×1,25–1,9 по ширине экрана); листание ‹ › — мягкая смена содержимого; блок «Тот же бренд и назначение» — только товары того же бренда с общей задачей из данных; «Запросить информацию» и «Помочь с подбором». Закрытие: Esc, крестик, клик по затемнению; фокус возвращается на «Быстрый просмотр» карточки; Tab не выходит из окна |
| **Смена фильтров** | приём FLIP: оставшиеся карточки плавно переезжают, пришедшие проявляются с небольшим смещением, ушедшие — «призраки» (копия поверх сетки, без `id` и `data-*`, `aria-hidden`, `inert`) растворяются за 0,22 с. Состояние (`hidden`, счётчик «Найдено», чипы, адрес) меняется **сразу**, а не после анимации; каждый следующий вызов отменяет незаконченные анимации и продолжает с их текущих положений — быстрые смены не накладываются. Анимируются только карточки в зоне видимости |
| **Быстрые категории** | уже были: плитки `cat-tile` — те же категории из `data/catalog.json` (Эстетика лица, Химические пилинги, Фотозащита, Домашний уход, Волосы и кожа головы, Эстетика тела, а также Декоративная косметика и Аппаратные решения). Витрина ничего не выдумывает и не дублирует |
| **«Помочь с подбором»** | кнопка в строке результатов и в окне товара — через существующую Стеллу (`A.stella.ask`), второго помощника нет. Из каталога передаются выбранные категория, бренд, назначение, тип, запрос и число найденных товаров; от товара — бренд, название, категория, вид, назначение. Ответ даёт встроенный «мозг» Стеллы по данным сайта (работает и на GitHub Pages); режим с ИИ — только при подключённом сервере (см. раздел про Стеллу) |

**Доступность и производительность.** Анимируются `opacity` и `transform` (у перелёта — размер одного небольшого элемента). `prefers-reduced-motion: reduce` — только прозрачность: без подъёма, увеличения, каскада со сдвигом, перелёта и призраков. «Лёгкий режим» (`html.lite`, включается при медленных кадрах) — без перелёта, призраков и каскада. Горизонтальной прокрутки анимации не создают. Если файлы витрины не загрузились, каталог работает как раньше (проверено).

**Фото товаров.** У всех 30 товаров фото пока нет (`products.json → image` пусто), на карточках честные иллюстрации упаковки. Витрина их не подменяет; когда в админке («Товары по брендам») появятся фото, они подхватятся: у `.art-photo` масштабируется картинка, в окне просмотра показывается крупно. Серий и «дополняющих» товаров в данных нет, поэтому связь только «бренд + общая задача».

**Проверка:** `node tools/check-gallery.js` (после `node tools/build.js`; нужны Playwright и Chromium): компьютер и телефон, `prefers-reduced-motion`, «лёгкий режим», медленное соединение (1,6 Мбит/с, 150 мс), отказ загрузки файлов витрины, ошибки консоли; ожидаемые числа берутся из данных, а не со страницы.

**Публикация на GitHub Pages.** Сайт статический: все страницы, CSS и JS лежат в репозитории готовыми. 1) `node tools/build.js` и `node tools/check.js`; 2) закоммитить всё, включая пересобранные `*.html` и `js/data.js`; 3) слить ветку в ту, из которой публикуется сайт (Settings → Pages → Build and deployment → «Deploy from a branch», папка `/ (root)`); 4) через 1–2 минуты открыть `https://<владелец>.github.io/<репозиторий>/catalog.html` и обновить страницу с Ctrl+F5 — файлам добавлен хеш версии (`?v=…`), кэш сбрасывается сам. Всё, что здесь описано, работает без сервера. **Серверной части требуют** только отправка заявок (`/api/lead`), админка и ИИ-режим Стеллы.

## Каталог-шоурум (extras.showroom)

Страница `catalog.html` — интерактивная витрина премиального бутика по визуальным референсам (композиция 1536×1024: левая панель фильтров, заголовок и категории по центру, карточка товара справа вверху, десять подиумов в одну линию на переднем плане, ниша со стеклянными полками справа — без предметов на заднем плане, «Рекомендуем» в стеклянной панели). Сцена занимает всю ширину окна (до 2400 px, дальше края плавно уходят в фон). Блоки «Недавно просмотренные» и «Подборки по задачам» на этой странице убраны (на страницах товаров «Недавно просмотренные» остаются). Левая панель фильтров ужимается по высоте окна, чтобы при заходе быть видной целиком. Нижний край сцены плавно растворяется в фоне страницы: цвет градиента считается по реальному фону страницы в месте стыка (`seam()` в `js/showroom.js`), шва нет. **Наведение:** товар выходит вперёд (z-index 60, ×1,16, лёгкий подъём, свет под ним), соседи и подиумы остаются как есть (никакой полупрозрачности); подиум — продолжение товара: наведение и нажатие по камню работают как по упаковке. **Выбор:** выбранный товар выходит над сценой ещё сильнее (z-index 70, ×1,3), сцена притемняется одной вуалью (`.shw-veil`); пока открыта карточка, наведение на другие предметы ничего не двигает и не меняет карточку, а нажатие на другой предмет переключает выбор. **Стелла:** вместо «Помочь с подбором» в полосе преимуществ — кнопка «Спросить Стеллу» с её жемчужинкой; она передаёт Стелле выбранные фильтры (`gal-help`). **Цвет:** на странице каталога синий акцент сайта заменён тёмно-синим (`--blue` → `--navy` на `body[data-page="catalog"]`): логотип и меню в шапке, «Стать партнёром», фокус, полоса прокрутки. **Фон под витриной:** текстуры через систему фоновых вставок (за «Подберите по задаче» — тонкие волнистые линии `ribbon`, за брендами — шёлк; «чистая вода» `assets/bg/water-a.webp` — по краям большого списка); настоящие ветки растения (`assets/bg/plant-a.webp`, Blender, без тени; `tools/bg-render/plant.py`) заходят с краёв экрана и слегка покачиваются, у большого списка — по обе стороны от колонки; в витрине над сценой медленно плывут светлые «пылинки» (`.shw-motes`, отключаются в «лёгком режиме»). **Появление:** плитки «Подберите по задаче», «Выберите направление ухода», «Бренды в галерее» и карточки большого каталога появляются анимацией `axTile` (keyframes, а не transition): «лёгкий режим» и системная настройка «уменьшить движение» её не гасят — на этом сайте анимации работают всегда; внутри карточек подиум и упаковка поднимаются по очереди. Под витриной — полоса преимуществ, «Подберите по задаче», «Коллекции» (живые мини-экспозиции по категориям), «Бренды в галерее» и свёрнутый «Весь ассортимент списком»; единая дизайн-система описана в `docs/DESIGN-SYSTEM.md`. Включается флагом `extras.showroom` (нужны `extras.enabled` и `extras.gallery`); выключен — прежний каталог со всеми карточками. Главная, вступление и другие страницы не затронуты.

| Слой (сзади вперёд) | Из чего сделан |
|---|---|
| Стена, пол, окно с косым светом, тени | 3D-рендер (Blender/Cycles) `assets/showroom/layer-shell.webp` |
| Правая арка, ниша, три стеклянные полки с тёплой LED-подсветкой | рендер `layer-niche.webp` |
| Левая арка (толстая рама) | рендер `layer-ring.webp` |
| Платформа и ступени из травертина | рендер `layer-dais.webp` |
| Оливковые ветки в вазе | рендер `layer-plant.webp` |
| Подиумы (10 штук в одну линию: высота и ряд чередуются, у каждого товара свой подиум, подиумы не перекрываются; три «композиции» по категориям) | HTML/CSS, боковая стенка и верхняя грань — спрайты `pod-body.webp`, `pod-cap.webp` из того же рендера |
| Товары | HTML-кнопки: 3D-макеты упаковки `pack-*.webp` (рендер Blender, без текста и логотипов) или настоящие фото |
| Панель фильтров, заголовок и категории, карточка товара, «Рекомендуем», листание | HTML/CSS: панели поверх сцены — левая и «Рекомендуем» из матового стекла без `backdrop-filter` (под ними лежит размытая копия сцены `glass.webp`, её собирает `tools/showroom-assets/glass.py`); значения фильтров живут в настоящих `<select>` (`#f-brand`, `#f-cat`, `#f-task`, `#f-kind`, `#f-sort`) — поэтому работают адреса с параметрами, Стелла и `gallery.js` |

Слои — это **отдельные PNG/WebP одной 3D-сцены с одной камеры**: делается один полный рендер (все объекты, общий свет, тени и отражения), второй — «чистая подложка» (только стена, пол и окно), и по одной маске на группу объектов (ниша, арка, платформа со ступенями, растение). Слой группы — это пиксели полного рендера с маской в роли прозрачности, подложка — полный рендер вне объектов и чистая подложка под ними, поэтому швов и дыр нет, а тени/отражённый свет объектов лежат в подложке и в слоях. Один общий «картинка-фон» не используется: слои, подиумы, товары, панели и карточки — отдельные элементы страницы. Исходники: `tools/showroom-assets/scene.py` (сцена и слои, координаты опорных точек — `layers.json → anchors`), `tools/showroom-assets/packs.py` (макеты упаковки). Перерисовать: `pip install bpy numpy scipy pillow`, затем `SCENE_W=1920 SCENE_SPP=80 python3 tools/showroom-assets/scene.py all` (≈25 минут на 4 ядрах; `… scene.py preview` — быстрый кадр; для проверки без дыр: `SCENE_W=768 SCENE_SPP=16 …`) и `python3 tools/showroom-assets/packs.py` (≈8 минут; переменные `PACK_RES`, `PACK_SAMPLES`, `PACK_H`, `PACK_SHARP`).

**Планшет и телефон (до 1100 px).** Та же витрина, «героем» на первый экран: сцена на всю ширину и высоту, поверх неё заголовок и категории, вверху стеклянная полоса «поиск + Фильтры» (фильтры раскрываются стеклянной панелью поверх сцены), внизу стеклянная плашка товара и «док» листания. Всё помещается на одном экране без сдвига: на планшете десять подиумов стоят в одну линию, на телефоне — в две полки по пять (задний ряд на каменной полке); масштаб считает `measure()` в `js/showroom.js` по свободной ширине и высоте (между заголовком и плашкой товара), на низких экранах заголовок прячется. «Рекомендуем», преимущества, коллекции и остальное идут ниже.

**Поведение (`js/showroom.js`).** Десять товаров на странице, все на переднем плане, каждый на своём подиуме (подиумы не перекрываются, упаковка занимает не больше 82 % его ширины; главный товар — на самом высоком подиуме и крупнее); остальные — на следующих страницах (стрелки справа, «1 / 3»). Предметов на заднем плане (в нише) нет. Полный список со всеми карточками — внизу в свёрнутом блоке «Весь ассортимент списком» (кнопка «Смотреть весь список» раскрывает его). Смена категории, фильтра, поиска и сортировки: ушедшие товары растворяются, оставшиеся переезжают (FLIP), новые появляются, подиумы меняют высоту (три композиции по категории), архитектура не перерисовывается. Наведение («прожектор»): товар приподнимается и увеличивается (×1,18, растёт вверх от основания), под ним вспыхивает свет, подиум светлеет и чуть поднимается, остальные товары и подиумы мягко отступают; сведения о товаре показывает карточка справа (подпись не всплывает). Выбор (клик/тап/Enter): остальные приглушаются, включается световое пятно, карточка раскрывается, приезжает к товару и соединяется с ним тонкой линией; в ней «Подробнее» (страница товара), «Запросить» (форма заявки), «Быстрый просмотр», «Помочь с подбором» (Стелла получает товар); закрыть — крестик, Esc или клик по пустому месту сцены. Шапка сайта над сценой прозрачная, при прокрутке возвращается привычная молочная (`html.shw-top`).

**Телефон и планшет** (≤ 1100 px): та же сцена (7 подиумов, ниша, арки, растение) показывается крупно; если по ширине не помещается — сдвигается пальцем или стрелками. Интерфейс идёт обычным потоком: те же стеклянные панели, фильтры за кнопкой «Фильтры» (те же галочки), категории — лентой, карточка товара под сценой.

**Изображения товаров.** По решению заказчика сцена, «Рекомендуем» и карточки полного списка показывают **3D-макеты упаковки** (без текста и логотипов; в карточке помечены «условное изображение»). Настоящие фото из `data/products.json → image` включаются флагом `extras.showroomPhotos` (в админке: «Шоурум: настоящие фото товаров вместо 3D-макетов»; по умолчанию выключено): тогда товар с фото показывается как есть, без искажений (прозрачные PNG/WebP ставятся напрямую, непрозрачные — с `multiply`); подготовить фото помогает `tools/product-photo.py` (вырезание фона). В проекте есть три настоящих снимка упаковки (`assets/photos/`: Keenwell Neuro-K, Dermatime Sensi-Well, Iraltone Fortifying Shampoo) — к товарам каталога не привязаны, чтобы не придумывать позиции.

**Откат.** `restore/catalog-before-showroom` (коммит `e212756`) — каталог до шоурума; `restore/catalog-before-gallery` (`3404682`) — до витрины. Серверные теги недоступны, поэтому точки записаны здесь: `git checkout e212756`. Быстро выключить шоурум: `"showroom": false` в `data/redesign.json` и `node tools/build.js`.

**Проверка:** `node tools/check-showroom.js` (после `node tools/build.js`; Playwright и Chromium): сцена из слоёв, товары стоят на подиумах, шапка, фильтры слева, категории, поиск, сортировка, листание, наведение, выбор, карточка и все её кнопки (в т. ч. Стелла), «Рекомендуем», полный список, планшет и телефон, `prefers-reduced-motion`, «лёгкий режим». Вес слоёв сцены (1920 px, WebP) — около 100 КБ, упаковок (840 px по высоте) — около 200 КБ: `du -sh assets/showroom`.

**Публикация на GitHub Pages.** Все пути относительные (`../assets/showroom/…` в CSS, `assets/showroom/…` + `data-root` в HTML и JS): `node tools/build.js`, затем закоммитить сгенерированные файлы вместе с `assets/showroom/`.

## Фоновые вставки (текстуры за содержимым страниц)

Восемь фоновых картинок — крем-волны, мазок крема, узкий мазок («свотч» — на блоке «Подбор по задаче»), молочный шёлк, линии и сетка, прозрачные плёнки, капля и пипетка, молекулы (редко: «Обучение», «Партнёры», один блок главной) — лежат мягкими пятнами на заднем плане страниц и «разбавляют» фон. Они есть на каталоге, брендах и страницах брендов, товарах, обучении и мероприятиях, новостях, компании, контактах, партнёрах, поиске и юридических страницах, а также на главной — на всех блоках ниже героя. Рендеров упаковки (баночек, флаконов, туб) на фоне нет — убраны по просьбе заказчика. **На самом герое (первый экран с девушкой и шаром), во вступлении с баночкой, в бегущей строке брендов и в блоке «Астрея в цифрах» вставок нет** (по просьбе заказчика). На странице «Компания» за заголовком только крупный логотип «Астрея», без узора. Пузырьков, жемчуга и россыпи капель на фоне нет (убраны по просьбе заказчика, вместо них — мазок крема; «завиток» из спиральных валиков, флаконы-«колбочки» с пипеткой, тубы и флаконы с дозаторами тоже убраны); на страницах брендов только крем, шёлк, мазок и плёнки, без молекул и упаковки, и у разных брендов фон разный (`variants` в плане страницы: страницы с одним ключом получают варианты по очереди).

* Картинки: `assets/bg/<имя>.webp` (+ `<имя>-m.webp` для телефона), в сумме около полумегабайта; грузятся лениво, когда блок подходит к экрану, и плавно проявляются; при включённой экономии трафика не грузятся вовсе. Рисуются в `tools/bg-render/` (Blender + numpy), как перерисовать — `tools/bg-render/README.md`.
* Размещение: `data/redesign.json → backdrops` — какая текстура и где на каждой странице (полоса сверху, полоса снизу, отдельные блоки), сила, список страниц без вставок (`skipPages`, сейчас пуст). После правки — `node tools/build.js`.
* Выключить совсем: `backdrops.enabled = false` (CSS и JS тогда не подключаются). Убрать с одной страницы — удалить её запись из `backdrops.pages`.
* Текстуры накладываются умножением (`mix-blend-mode: multiply`), лежат под содержимым и не ловят клики; серый текст на страницах с текстурой чуть темнее, чтобы контраст был не ниже WCAG AA. Проверка: `npm run check:bg` (файлы, разметка, подгрузка, переходы без перезагрузки, контраст по снимку страницы).
