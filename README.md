# Астрея — сайт дистрибьютора профессиональной косметики

Статический многостраничный сайт без бэкенда и без внешних зависимостей. Страницы генерируются из `data/*.json` скриптом на Node.js
(только стандартная библиотека), поэтому сайт открывается с любого хостинга, в том числе с GitHub Pages, и с диска.

## Структура

```
index.html catalog.html brands.html training.html news.html company.html contacts.html partners.html search.html privacy.html terms.html 404.html
brands/<бренд>.html      страницы брендов (9)
products/<товар>.html    страницы товаров (30)
training/<мероприятие>.html   страницы мероприятий (7)
news/<новость>.html      страницы новостей (9)
css/   base · components · pages · responsive · motion · redesign (слой доработок) · backdrops (фоновые вставки)
js/    shared (общий код для Node и браузера) · data (генерируется) · core · motion · pages · hero-mark · redesign (слой доработок) · backdrops (фоновые вставки)
assets/ favicon, иконки, og-image; assets/brands/ — логотипы брендов; assets/products/ — фото товаров (ставятся в админке, раздел «Товары по брендам»; пока фото нет, на карточке рисуется иллюстрация упаковки); assets/photos/ — фото для слоя доработок; assets/jar/ — кадры вступления с баночкой (рендер Blender, см. tools/jar-render); assets/bg/ — фоновые текстуры страниц (см. tools/bg-render)
data/  ВСЕ данные и тексты сайта (см. data/README.md)
src/   шаблоны страниц (функции, возвращающие HTML)
tools/ build.js — сборка · check.js — проверка · bundle.js — автономная сборка · redesign.js — включить/выключить слой доработок
server/ сервер заявок и админка сайта (Node.js без зависимостей) — см. server/README.md
sitemap.xml robots.txt
```

HTML-файлы в корне и в `brands/ products/ training/ news/` — **результат сборки**: не правьте их руками, меняйте `data/` или `src/` и запускайте сборку.
`404.html` — страница «Такой страницы нет»: GitHub Pages сам отдаёт её на любой неверный адрес (на любой глубине), поэтому ссылки в ней идут от корня сайта (`/astreya/…`), а не «../»; из папки напрямую (file://) она не откроется — это нормально. Не попадает в sitemap (`noindex`). Аудит (`npm run audit`) открывает её по http.

## Сборка и проверка

```bash
node tools/build.js      # собрать сайт (страницы, js/data.js, sitemap.xml, robots.txt)
node tools/check.js      # проверить: битые ссылки и якоря, один <h1>, уникальные title/description, canonical, порядок заголовков
```

Требуется Node.js 16+. `npm run build` / `npm run check` делают то же самое.
В ссылки на CSS/JS при сборке добавляется версия (`?v=…`, хэш файлов и данных), поэтому после публикации браузер не показывает устаревшие стили; страницы при переходах запрашиваются с перепроверкой.
Автономный файл (все страницы в одном HTML, для предпросмотра или публикации там, где нет обычных файлов): `node tools/build.js --bundle=astreya.html`.

Поля, которых нет в данных (объём, артикул, показания, способ применения, документы, программа мероприятия, реквизиты), на страницах показываются как
«Уточняется — запросите у менеджера»: ничего не выдумывается. Как только вы заполните поле в JSON, соответствующий блок появится сам.
Всё демонстрационное помечено (`demo: true` и текст в подвале `demoNotice` в `site.json` — удалите его, когда данные станут реальными;
вместе с ним включится разметка Product/Event/NewsArticle для поисковиков).

## Переходы между страницами и обновление

Поведение как в прежней (одностраничной) версии сайта:

* **Обновление / первая загрузка любой страницы** — заставка с собирающимся логотипом (~2,2 с, по клику пропускается), затем полосы шторки поднимаются.
* **Переход по ссылке внутри сайта** — без перезагрузки: полосы шторки закрываются (820 мс) с титром раздела, содержимое `<main>` подменяется настоящей страницей
  (тот же файл, что видят поисковики), полосы поднимаются (700 мс), блоки появляются через 470 мс. Работает кнопка «Назад», адрес и заголовок вкладки меняются.
  Если подмена невозможна (файл открыт с диска, нет сети), выполняется обычный переход по ссылке под той же шторкой.
* **Поиск** (форма в шапке/в окне поиска/на странице результатов, подсказки, «Все результаты») открывает результаты **тихо** — без шторки и заставки: страница подменяется сразу и мягко проявляется
  (`go(url, push, quiet)` в `js/motion.js`; при открытии с диска — обычная загрузка, но ранний скрипт в `<head>` ставит `nav-quiet`, и заставка не показывается).
* При подмене страницы подключаются недостающие стили и скрипты (`syncAssets`): у главной есть `css/jar.css`/`js/jar.js`, у других страниц их нет — без этого возврат на главную по логотипу
  из каталога давал секцию вступления без оформления.
* Тайминги — в `js/motion.js` (`go`) и `css/motion.css` (блок `curtain`).
* **Лого и ссылки на главную** ведут к основной странице — герою, а не в начало вступления с баночкой: после перехода (и на самой главной по клику на лого) страница прокручивается к герою (`M.heroTop`/`M.scrollHome` в `js/motion.js`).
  Вступление остаётся выше героя: до него можно долистать вверх, кадры при этом перематываются назад. Заход на главную по адресу или в новой вкладке открывается с вступления, а **обновление страницы (F5, «перезагрузить») на главной открывает героя** — вступление показывается при заходе на сайт, а не при каждом обновлении (определяется по Navigation Timing, `js/motion.js`). Проверка: `npm run check:logo`.

## Формы

Формы (партнёр, запись на мероприятие, запрос по товару, вопрос, обратный звонок, подписка на новости) **отправляют заявки в админку** (сервер из `server/`): `data/site.json → formEndpoint` по умолчанию `/api/lead`.

* **Сайт открыт через сервер** (`npm run admin` → <http://localhost:8080/>, либо сайт и сервер на одном хостинге): заявка сразу появляется в админке, в разделе «Заявки».
* **Сайт на GitHub Pages (статический хостинг):** `/api/lead` там не существует, форма честно покажет «Не удалось отправить заявку» с телефоном и письмом как запасным путём. Чтобы заявки с Pages попадали в админку,
  разместите сервер на хостинге с https и пропишите его полный адрес (`https://<сервер>/api/lead`) в `formEndpoint` — кнопкой в админке («Настройки и заявки → Подключение форм сайта») или вручную.
* **Режим письма (mailto)** остаётся для пустого `formEndpoint`: готовится письмо на `contacts.email`, интерфейс пишет «Заявка подготовлена». В автономном файле-предпросмотре (`build.js --bundle`, артефакт) сервера нет, поэтому там всегда этот режим.

Формат запроса: `POST` с JSON `{type, context, name, phone, email, city, org, spec, msg, page, sent_at, consent, fill_ms}`; сервер проверяет поля, защищает от спама, сохраняет заявку и присылает уведомление.
Ответ 2xx — успех; 422 — поля подсвечиваются, данные остаются; 429 — «слишком много заявок»; обрыв сети/другая ошибка — сообщение с сохранёнными данными и запасными контактами (телефон, письмо).
В форме есть скрытое поле-ловушка для ботов; `fill_ms` — сколько форму заполняли (бот отправляет мгновенно). Любой другой бэкенд с тем же JSON тоже подойдёт.

## Админка и заявки

`server/` — сервер (Node.js 18+, без зависимостей): приём заявок, админка на `/admin/` (заявки, правка содержимого, картинки, пересборка, публикация, пользователи, уведомления), раздача сайта.
GitHub Pages не выполняет серверный код, поэтому сервер запускается отдельно (VPS / Render / Docker); сайт при этом может оставаться на Pages. Установка, переменные окружения, безопасность,
подключение форм и тесты — в [`server/README.md`](server/README.md). Быстрый старт: `npm run admin` → <http://localhost:8080/admin/>.

## Аналитика

Реальных идентификаторов нет. Все события уходят в `window.dataLayer` и в DOM-событие `astreya:track`; если на странице подключён `gtag`/`ym`, вызываются и они
(укажите номера в `js/core.js` → `A.config`). События: `partner_cta` (кнопки «Стать партнёром», с `place`), `form_open`, `form_submit`, `form_error`,
`phone_click`, `email_click`, `messenger_click`, `catalog_click`, `catalog_view`, `catalog_filter`, `product_card_click`, `product_view`, `product_request`,
`event_register`, `brand_card_click`, `search`, `search_result_click`, `picker_select`. Разметка: атрибуты `data-track="…" data-place="…"`.

## SEO

У каждой страницы свои `title`, `description`, `canonical`, Open Graph/Twitter, favicon; JSON-LD: Organization + WebSite (главная), BreadcrumbList, FAQPage (обучение).
`robots.txt` и `sitemap.xml` собираются автоматически (страница поиска закрыта от индексации). Адрес сайта для canonical/sitemap — `site.json` → `url`.

## Помощник («Астрея» — чат справа внизу)

Включается флагом `extras.assistant`; файлы — `js/assistant.js`, стили в `css/extras.css`, база знаний `js/kb.js` (собирает `tools/build.js` из `data/*.json` и подгружает чат при первом открытии), серверная часть — `server/lib/assistant.js`.

* **Встроенный режим работает всегда** (в том числе на GitHub Pages и в автономном файле): отвечает прямо в браузере по данным сайта и **ничего никуда не отправляет**. Умеет подбор по задаче (карточки товаров + оговорка «не назначение»), рассказ о товаре и бренде, расписание и запись, условия партнёрства и скидки, контакты по городам, «заказать звонок», вопрос менеджеру, добавление в список запроса и сравнение. Цены, наличие, сроки, сертификаты и медицинские рекомендации — **честно «этого на сайте нет»**, с предложением связаться с менеджером. Диалог хранится в `sessionStorage` вкладки.
* **ИИ-режим (необязательный)** для свободных вопросов: сервер из `server/` отправляет диалог в Anthropic API и отдаёт ответ потоком. Включается переменными окружения: `ANTHROPIC_API_KEY`, `ASSISTANT_MODEL` (идентификатор модели — **обязательно, в репозитории намеренно не прописан**; берите актуальный из документации Anthropic), необязательно `ASSISTANT_MAX_TOKENS` (700), `ASSISTANT_RATE` (сообщений с адреса за 10 минут, 20), `ASSISTANT_DAILY` (всего за сутки, 400). Пакет `@anthropic-ai/sdk` — необязательная зависимость (`npm install` в корне; в Docker ставится сам). Нет ключа, модели, пакета или лимит исчерпан — чат молча работает во встроенном режиме. Адрес берётся из `formEndpoint` (`…/api/lead` → `…/api/assistant`), проверить состояние: `GET /api/assistant/status`.
* **Инструкция модели собирается из данных сайта** (о компании, контакты, представительства, партнёрам, обучение, бренды, задачи, товары, мероприятия, новости) и запрещает выдумывать цены, наличие, сроки, состав, акции и даты, давать медицинские советы и собирать личные данные. Ответ может заканчиваться маркерами `[[product:ID]]`, `[[form:ТИП]]`, `[[link:путь]]` — они становятся карточками и кнопками **только если ID/путь есть в данных сайта**. Меняете данные — `npm run build`, и помощник «знает» новое.
* **Приватность:** в ИИ-режиме текст вопросов уходит на ваш сервер и оттуда в сервис ИИ (в интерфейсе об этом сказано, просьба не вводить личные данные); сервер не сохраняет диалоги и не пишет их в журнал. Защита: только с разрешённых сайтов (CORS), ограничение частоты по адресу и в сутки, лимит длины, обрыв запроса при закрытии чата.
* **Выключить:** `"assistant": false` и `npm run build` (файл `js/kb.js` удалится). Проверка: `npm run check:extras` (встроенные ответы на все товары, бренды и задачи каталога) и `node --test server/test/assistant.test.js` (ИИ-режим на поддельном клиенте, без сети).

## Фоновые вставки (текстуры за содержимым страниц)

Восемь фоновых картинок — крем-волны, мазок крема, узкий мазок («свотч» — на блоке «Подбор по задаче»), молочный шёлк, линии и сетка, прозрачные плёнки, капля и пипетка, молекулы (редко: «Обучение», «Партнёры», один блок главной) — лежат мягкими пятнами на заднем плане страниц и «разбавляют» фон. Они есть на каталоге, брендах и страницах брендов, товарах, обучении и мероприятиях, новостях, компании, контактах, партнёрах, поиске и юридических страницах, а также на главной — на всех блоках ниже героя. Рендеров упаковки (баночек, флаконов, туб) на фоне нет — убраны по просьбе заказчика. **На самом герое (первый экран с девушкой и шаром), во вступлении с баночкой, в бегущей строке брендов и в блоке «Астрея в цифрах» вставок нет** (по просьбе заказчика). На странице «Компания» за заголовком только крупный логотип «Астрея», без узора. Пузырьков, жемчуга и россыпи капель на фоне нет (убраны по просьбе заказчика, вместо них — мазок крема; «завиток» из спиральных валиков, флаконы-«колбочки» с пипеткой, тубы и флаконы с дозаторами тоже убраны); на страницах брендов только крем, шёлк, мазок и плёнки, без молекул и упаковки, и у разных брендов фон разный (`variants` в плане страницы: страницы с одним ключом получают варианты по очереди).

* Картинки: `assets/bg/<имя>.webp` (+ `<имя>-m.webp` для телефона), в сумме около полумегабайта; грузятся лениво, когда блок подходит к экрану, и плавно проявляются; при включённой экономии трафика не грузятся вовсе. Рисуются в `tools/bg-render/` (Blender + numpy), как перерисовать — `tools/bg-render/README.md`.
* Размещение: `data/redesign.json → backdrops` — какая текстура и где на каждой странице (полоса сверху, полоса снизу, отдельные блоки), сила, список страниц без вставок (`skipPages`, сейчас пуст). После правки — `node tools/build.js`.
* Выключить совсем: `backdrops.enabled = false` (CSS и JS тогда не подключаются). Убрать с одной страницы — удалить её запись из `backdrops.pages`.
* Текстуры накладываются умножением (`mix-blend-mode: multiply`), лежат под содержимым и не ловят клики; серый текст на страницах с текстурой чуть темнее, чтобы контраст был не ниже WCAG AA. Проверка: `npm run check:bg` (файлы, разметка, подгрузка, переходы без перезагрузки, контраст по снимку страницы).

## Что сознательно не делалось на этом этапе

Безопасность (CSP, антиспам на сервере), оптимизация производительности, страница 404, серверная часть/CRM, онлайн-оплата, личный кабинет.
