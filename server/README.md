# Сервер заявок и админка сайта «Астрея»

Небольшой сервер на Node.js (без внешних зависимостей, Node 18+), который:

* **принимает заявки** с форм сайта (`POST /api/lead`), защищает от спама и сохраняет их;
* показывает **админку** на `/admin/`: заявки (статусы, комментарии, поиск, выгрузка в CSV), правка содержимого сайта (товары, бренды, мероприятия, новости, тексты, SEO), картинки, пересборка и публикация, пользователи, настройки уведомлений, журнал;
* присылает **уведомления** о новых заявках: Telegram, e-mail (SMTP), веб-хук (CRM);
* при желании **раздаёт сам сайт**.

> **Важно про GitHub Pages.** Pages — статический хостинг: серверный код там выполняться не может. Сайт может оставаться на Pages, но этот сервер нужно запустить **отдельно**
> (VPS, Render, Railway, Fly.io, Docker — см. ниже) и один раз указать его адрес в настройках форм. Если сайт открыт через этот же сервер (`http://localhost:8080/`), формы сразу шлют заявки в админку (в поставке `formEndpoint` = `/api/lead`). Для сайта на Pages без сервера форма покажет ошибку отправки — укажите адрес сервера (см. ниже).

## Быстрый старт (на своём компьютере)

```bash
node server/index.js
# Сервер сайта «Астрея»: http://localhost:8080/   админка: /admin/
#   Создан администратор.  Логин: admin   Пароль: xxxxxxxxxxxx   ← показывается один раз, при первом входе его нужно сменить
```

Откройте <http://localhost:8080/admin/>. Свой логин/пароль можно задать заранее: `ADMIN_LOGIN=ivan ADMIN_PASSWORD='Секрет-12345' node server/index.js` (только при первом запуске, пока нет пользователей).

Откройте сайт по адресу <http://localhost:8080/> (не файлом с диска!) и отправьте любую форму — заявка появится в админке, раздел «Заявки». Если формы всё ещё готовят письмо, откройте **Настройки и заявки → Подключение форм сайта → «Тот же сервер (/api/lead)» → «Записать в настройки сайта»**.

## Как заявки попадают с сайта на сервер

```
посетитель → форма на сайте (GitHub Pages) → POST https://<ваш-сервер>/api/lead → сервер → админка + уведомления
```

1. Разверните сервер на публичном адресе **с https** (например `https://api.astreya.ru`). Браузер не отправляет формы с https-сайта на http-сервер.
2. Войдите в админку → **Настройки и заявки**:
   * «Адрес приёма заявок» → `https://api.astreya.ru/api/lead` → «Записать в настройки сайта». Это меняет `data/site.json → formEndpoint` и пересобирает `js/data.js`.
   * Адрес сайта из `data/site.json → url` (например `https://aassstrixx.github.io`) разрешён автоматически. Другие сайты добавьте в «Сайты, с которых принимаются заявки».
3. Опубликуйте обновлённый сайт на GitHub Pages (кнопка «Опубликовать» при `PUBLISH_GIT=1`, либо вручную закоммитьте `data/site.json` и `js/data.js`).
4. Отправьте тестовую заявку с сайта — она появится в разделе «Заявки». Затем настройте уведомления и нажмите «Сохранить и отправить тест».

Если сайт и сервер работают на одном адресе (сервер сам раздаёт сайт), в качестве адреса используйте `/api/lead` — CORS не нужен.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | `8080`, `0.0.0.0` | Где слушать |
| `SITE_ROOT` | корень репозитория | Папка сайта (в ней `tools/build.js`, `data/`, готовые страницы) |
| `DATA_DIR` | `server/data` | Приватные данные: заявки, пользователи, сессии, резервные копии, журнал, настройки |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | `admin`, случайный | Первый администратор (только когда пользователей ещё нет) |
| `TRUST_PROXY` | `0` | `1`, если сервер за nginx/Render/Cloudflare: адрес клиента берётся из `X-Forwarded-For`, https — из `X-Forwarded-Proto`. **Без этого за прокси все посетители «с одного адреса».** Включайте только если сервер недоступен напрямую из интернета (иначе адрес можно подделать и обойти ограничения) |
| `SECURE_COOKIES` | `0` | `1` — cookie админки только по https (включайте на публичном сервере) |
| `PUBLIC_URL` | — | Публичный адрес сервера: ссылка на админку в уведомлениях |
| `PUBLISH_GIT` | `0` | `1` — включает «Опубликовать» (git add/commit/push из админки) |
| `GIT_AUTHOR_EMAIL` | `admin@localhost` | E-mail в коммитах публикации |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | Только для тестов |

Всё остальное (разрешённые сайты, лимиты, уведомления, срок хранения) настраивается в админке и хранится в `DATA_DIR/settings.json`.

## Развёртывание

### Вариант 1. Docker (рекомендуется)

> Файлы Docker (`server/Dockerfile`, `server/docker-entrypoint.sh`) проверены только по логике (клонирование репозитория при первом запуске и запуск сервера работают); сам образ в среде разработки не собирался — при первой сборке проверьте его.

```bash
docker build -f server/Dockerfile -t astreya-server .
docker run -d --name astreya -p 8080:8080 \
  -v astreya-data:/data -v astreya-site:/site \
  -e ADMIN_LOGIN=admin -e ADMIN_PASSWORD='Придумайте-пароль-1' \
  -e SECURE_COOKIES=1 -e PUBLIC_URL=https://api.astreya.ru \
  -e SITE_REPO='https://x-access-token:<ТОКЕН>@github.com/aassstrixx/astreya.git' -e SITE_BRANCH=<ветка Pages> -e PUBLISH_GIT=1 \
  astreya-server
```

* `/data` — заявки и пользователи: **делайте резервные копии этого тома**.
* `SITE_REPO` + `PUBLISH_GIT=1` — полный режим: сервер клонирует репозиторий сайта, правки из админки пересобирают страницы, а «Опубликовать» отправляет их в GitHub (Pages обновится сам).
  Токен — fine-grained, **только этот репозиторий, право Contents: Read and write**. Без `SITE_REPO` сервер использует копию сайта из образа: заявки и админка заявок работают, а правки содержимого живут до пересборки образа.
* Поставьте перед контейнером https-прокси (Caddy, nginx, Cloudflare, встроенный https Render/Railway/Fly) и оставьте `TRUST_PROXY=1`.

### Вариант 2. VPS без Docker

```bash
git clone <репозиторий> /srv/astreya && cd /srv/astreya
DATA_DIR=/var/lib/astreya TRUST_PROXY=1 SECURE_COOKIES=1 PORT=8080 node server/index.js
```

Для автозапуска — systemd:

```ini
[Service]
WorkingDirectory=/srv/astreya
Environment=DATA_DIR=/var/lib/astreya TRUST_PROXY=1 SECURE_COOKIES=1 PORT=8080 PUBLISH_GIT=1
ExecStart=/usr/bin/node server/index.js
Restart=always
User=astreya
```

Пример Caddy: `api.astreya.ru { reverse_proxy localhost:8080 }` (https-сертификат выпускается автоматически).

### Вариант 3. Render / Railway / Fly.io

Запуск: `node server/index.js`; переменные из таблицы выше. **Нужен постоянный диск**, примонтированный в `DATA_DIR` (иначе заявки пропадут при перезапуске). Бесплатные «засыпающие» тарифы не подходят: первая заявка после простоя может потеряться.

## Админка

| Раздел | Что делает | Кто |
|---|---|---|
| **Обзор** | что требует внимания: новые заявки, счётчики товаров/новостей/страниц, состояние сборки, «здоровье сайта» (товары без описания, нет ближайших мероприятий, пропавшие файлы…) со ссылками «Исправить», быстрые действия, кнопка **«Полная проверка сайта»** (валидатор HTML, SEO, ссылки, изображения, доступность — `tools/audit.js`), последние действия | админ |
| **Заявки** | список с вкладками и поиском, карточка (контакты, сообщение, страница, статус, комментарии, история), CSV, обновление каждые 30 с | админ, менеджер |
| **Содержимое сайта** | формы для товаров, брендов, мероприятий, новостей (добавить/изменить/копия/удалить), тексты страниц, SEO, контакты, главная, справочники, преподаватели, FAQ; история версий с восстановлением | админ |
| **Товары по брендам** | вкладки по брендам, товары карточками: **добавить** товар бренду (название, категория, вид, задачи, описание, объём, артикул, показания, состав, применение), **править**, **убрать**, **копировать**, менять порядок ↑↓; **фото**: кнопкой «Фото» (загрузка или выбор из папки `assets/products`) или перетаскиванием снимка на карточку. Большие снимки уменьшаются в браузере до 1400 px и сохраняются в WebP; фото видно на карточке в каталоге и у бренда, на странице товара, на главной и в превью для соцсетей. Каждое действие сразу сохраняется и обновляет сайт; удалить товар, на который ссылаются новости или главная, сервер не даст. Документы и подробные характеристики — в «Содержимое сайта → Товары» | админ |
| **Страницы** | конструктор своих страниц: шаблон → блоки (текст, картинка, карточки, список, две колонки, шаги, цифры, вопросы и ответы, призыв, форма заявки), порядок и дублирование блоков, счётчики SEO-описания, чекбоксы «Опубликована» / «В меню» / «Не показывать в Google», живой предпросмотр рядом. Страница собирается в `pages/<адрес>.html`, попадает в поиск по сайту, карту сайта и (по желанию) в меню. Хранится в `data/pages.json` | админ |
| **Оформление** | две вкладки: **Меню сайта** (порядок, подписи, страницы — `data/menu.json`) и **Фоны страниц** (визуальный редактор плана фоновых вставок каждой страницы: текстуры-превью, положение 3×3, сила, фон на отдельных блоках, варианты, крупный логотип — `data/redesign.json → backdrops`) | админ |
| **Предпросмотр** | любая страница сайта в рамке 390 / 820 / 1280 / 1600 px | админ |
| **Картинки** | загрузка PNG/JPG/WebP/GIF (до 6 МБ), выбор в полях; файлы, на которые ссылается сайт, удалить нельзя | админ |
| **Публикация** | пересборка и проверка сайта, отправка в git | админ |
| **Настройки и заявки** | подключение форм, разрешённые сайты, защита от спама, Telegram / e-mail / веб-хук, пробное уведомление | админ |
| **Пользователи** | создание, роли, отключение, сброс пароля | админ |
| **Журнал** | кто и что менял | админ |

**Быстрый переход — Ctrl+K (⌘K).** Палитра команд открывается из любого раздела: разделы, «создать новость / товар / мероприятие / страницу» и поиск по товарам, брендам, новостям, мероприятиям и своим страницам (`GET /api/search?q=`). Стрелки выбирают, Enter открывает, Esc закрывает.

**Админка одним файлом (демо).** `npm run admin:demo` собирает `astreya-admin-demo.html` — всю админку в одном файле с данными сайта внутри: открывается двойным щелчком, без Node и сервера. Подходит, чтобы показать и «потрогать» интерфейс; правки живут только в открытой вкладке и сайт не меняют, а пересборка, проверка и публикация сайта на ней недоступны (на них честная пометка). Настоящая работа — `node server/index.js`.

Как это защищено:

* **Содержимое**: сохранение без изменений ничего не пишет. Файлы пишутся в стандартном виде (JSON с отступом 2 пробела): `data/content.json`, `data/news.json` и `data/redesign.json` набраны вручную в компактном стиле, поэтому при **первом реальном изменении** такого файла в git появится «шумный» дифф — переформатирование без смены содержимого.
* **Содержимое**: каждое сохранение проходит проверку (обязательные поля, уникальные `id`/`slug`, ссылки между файлами — бренд, категория, преподаватель…), создаёт **резервную копию** (последние 60 на раздел), пересобирает сайт и запускает `tools/check.js`.
  Если сайт не собрался или проверка нашла ошибки — **изменения автоматически откатываются**, а сообщение объясняет причину. Одновременные правки двух людей не затирают друг друга (проверка версии → «данные уже изменил кто-то другой»).
* **Вход**: пароли хранятся как scrypt-хэши (минимум 10 символов, буквы и цифры); сессии — случайные токены в `HttpOnly` + `SameSite=Strict` cookie, в файле лежат только их хэши; 12 часов жизни, 4 часа без активности;
  защита от подбора (5 неудач → блокировка на 15 минут, при повторах дольше); обязательная смена пароля после выдачи временного; CSRF-токен на всех изменяющих запросах; админка отдаётся с CSP и запретом встраивания.
* **Права**: «менеджер» видит и обрабатывает заявки, но не содержимое, настройки и пользователей; удалять заявки навсегда может только администратор. Нельзя удалить или лишить прав последнего администратора.
* **Заявки**: проверка полей и согласия на обработку данных (набор обязательных полей берётся из того же `js/shared.js`, по которому строятся формы), ограничение частоты (по умолчанию 5 за 10 минут и 30 за сутки с одного адреса — хранится хэш адреса, не сам адрес),
  скрытое поле-ловушка, отсечение повторов за 10 минут, признаки спама (ссылки, разметка). Слишком быстрая отправка не теряет заявку, а помечает её ⚠. Спам не уведомляет и скрыт из списка, но виден во вкладке «Спам».
  Выгрузка в CSV экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`, — защита от «CSV-инъекций» в Excel.
* **Файлы**: только растровые картинки с проверкой сигнатуры; имена очищаются (кириллица → латиница); SVG через админку не загружаются (риск скриптов) — кладите их в репозиторий вручную.
* **Секреты** (токен бота, пароль SMTP) не возвращаются в браузер: в форме показывается маска, при сохранении без изменений значение остаётся.

## Уведомления

* **Telegram**: создайте бота у `@BotFather` (токен), добавьте его в нужный чат и узнайте ID чата (например через `@userinfobot` или `https://api.telegram.org/bot<токен>/getUpdates`).
* **E-mail (SMTP)**: сервер, порт (587 — STARTTLS, 465 — сразу TLS), логин, пароль, отправитель, получатели через запятую. Сертификат сервера **проверяется всегда**.
* **Веб-хук**: `POST` с JSON `{"event": "lead.created", "text": "…", "lead": {id, type, name, phone, email, city, org, msg, context, page, created_at}}` — подходит для Bitrix24, amoCRM, n8n, Zapier, Make.

Заявка сохраняется всегда; сбой уведомления (например, Telegram недоступен) не теряет её и попадает в «Журнал» и `DATA_DIR/notify.log`. Кнопка «Сохранить и отправить тест» показывает результат по каждому каналу.

## Публикация на GitHub Pages

С `PUBLISH_GIT=1` кнопка «Опубликовать» делает `git add` (только `data/`, `assets/`, `js/`, `css/` и готовые страницы) → `git commit` от имени пользователя админки → `git push origin HEAD`.
Нужны `git` и права записи в репозиторий: токен в адресе `origin` (`https://x-access-token:<токен>@github.com/…`) или deploy-ключ. Токен не показывается в админке и сообщениях об ошибках.
Приватные данные (`DATA_DIR`) в репозиторий не попадают. Без `PUBLISH_GIT` меняйте репозиторий как раньше: `git pull` на сервере → проверьте → закоммитьте `data/` и собранные страницы.

## Командная строка

```bash
node server/cli.js create-admin ivan        # новый администратор (пароль спросит или сгенерирует)
node server/cli.js create-manager anna      # менеджер: только заявки
node server/cli.js reset-password ivan      # сброс пароля (временный, потребует смены)
node server/cli.js list-users
node server/cli.js export-leads leads.csv   # все заявки в CSV
node server/cli.js build                    # пересобрать и проверить сайт
node server/cli.js check                    # проверка конфигурации (формы, пользователи, cookie, уведомления)
```

## Проверка работоспособности

```bash
npm run test:server    # 47 проверок API: заявки, спам, права, содержимое с откатом, файлы, уведомления (веб-хук, Telegram, SMTP), git-публикация
npm run test:e2e-builder  # ~100 проверок нового интерфейса в браузере: «Обзор», конструктор страниц, «Оформление» (меню, фоны), «Предпросмотр», палитра Ctrl+K, «Где используется?» у картинок, доступность (axe, WCAG 2.2 AA) всех разделов, телефон 390 px
npm run arena:admin    # арена из 100 вариантов оформления интерфейса админки; итог — tools/arena-results/admin-ui.md
npm run test:e2e       # ~80 проверок в настоящем браузере (Playwright + Chromium): форма на сайте → заявка в админке → статус/комментарий/CSV → правка и публикация, права, телефон
```

Тесты поднимают сервер на временной копии сайта и ничего не меняют в репозитории. Для `test:e2e` нужен Playwright с Chromium (иначе проверка пропускается).

## Ограничения (честно)

* Данные хранятся в JSON-файлах, сервер — один процесс. Этого достаточно для сотен заявок в месяц и тысяч в год; для крупных объёмов или нескольких серверов нужна БД.
* Нет восстановления пароля по почте: сброс делает администратор в «Пользователях» или `server/cli.js reset-password`.
* Нет двухфакторной аутентификации; защита — длинные пароли, блокировка подбора и https.
* SMTP-клиент минимальный (PLAIN/LOGIN, текстовые письма). Для сложных сценариев используйте веб-хук и свою систему рассылок.
* Заявки — персональные данные. Храните `DATA_DIR` в защищённом месте, делайте резервные копии, при необходимости включите автоудаление закрытых заявок («Хранить закрытые заявки, дней»). Политика конфиденциальности на сайте пока — заглушка: её текст должен утвердить юрист.
